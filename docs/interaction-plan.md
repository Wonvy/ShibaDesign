## 1. 统一的操作规则

下面这些规则贯穿后面所有的条目，先定下来，各处照着做，用户学一次到处能用。

### 1.1 一切操作都是命令

按钮、顶部菜单、右键菜单、快捷键、命令面板都只引用命令 id（现在的按钮和快捷键已经是这样）。所以：

- 每个命令都要有 `enabled`，界面靠它把做不了的项变灰，而不是点了没反应。
- 做不了的原因由命令返回一个原因 id（比如 `instance-structure`：实例里的结构跟着主组件），界面翻译成悬停提示。内核仍然不产生给人看的文字。
- 右键菜单、顶部菜单、命令面板共用一份菜单项定义（见 [CTX-1](#ctx-1-菜单的补充)），不会出现"右键里有、菜单里没有"。

### 1.2 修饰键的含义

| 键                   | 含义                     | 用在哪里                                                                                                                     |
| -------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| Shift                | 约束                     | 移动锁定在 0° / 45° / 90°；缩放等比；旋转按 15°；画矩形、椭圆是正方形、正圆；钢笔、直线按 45°；列表里连选；画布上加选或减选  |
| Alt（Option）        | 复制，或者"从中心、单独" | 拖动对象、画板、图层、幻灯片时复制一份；缩放、画形状从中心往外；拖圆角控件只改这一个角；悬停时测距离；钢笔拖控制柄时断开对称 |
| ⌘（Windows 是 Ctrl） | 穿透、暂停               | 单击直接选中编组里面的对象；框选只选组里的成员；拖动中暂停吸附；缩放画框、画板时里面的东西不按约束跟着变                     |
| 空格                 | 移动视图或正在画的东西   | 平时按住是抓手（已有）；画形状、框选、拖动的过程中按住，挪动的是正在画的那个东西                                             |
| Esc                  | 一层层退出               | 先取消正在进行的拖动（回到拖动前），再退出当前模式（编辑文字、调整填充、画路径），最后取消选区                               |

- 拖到一半按下或松开修饰键立即生效，不用再动鼠标（已有，见 architecture.md 的"输入与快捷键"一节）。比如拖动时先没按 Alt，中途按下就变成复制，再松开又变回移动，原件回到拖动的位置。
- 在 Windows 的浏览器里，Alt 加字母可能被浏览器占用（Chrome 的 Alt+D 是地址栏、Alt+F 是菜单），要逐个实测；被占用的换别的键，桌面版（Electron）没有这个问题。
- Windows 上 Ctrl+Alt 等于 AltGr，有的键盘布局用它打字符。`mod+alt` 组合（⌥⌘K 这类）照常用，Figma 也是这样，但要知道这个限制。

### 1.3 反馈

- 拖动时在鼠标旁边显示数值：画形状、缩放显示"宽 × 高"，旋转显示角度，拖圆角显示半径，拖辅助线显示位置。选中对象时选区框下面常驻一个"宽 × 高"的小标签（UI 设计时很有用，可以在视图菜单里关掉）。
- 正在拖动时，画布底部显示一行修饰键提示（"Shift 锁定方向 · Alt 复制 · ⌘ 不吸附"），第一次用的人不用查文档。可以关掉。
- 拖动开始后，不相关的手柄（圆角控件、动作路径）先隐藏，松手再出来。

### 1.4 偏好和布局存在哪里

- 文档里的东西（辅助线、版面网格、约束、自动布局、圆角）存进文档，走事务，可以撤销，跟着文件走。
- 只和这台电脑、这个人有关的东西（面板布局、吸附开关、标尺显不显示、自定义快捷键）存在浏览器的 localStorage 里，读写都包在 try/catch 里（照 `Sidebar.tsx` 现在的写法），存不了就只在这次打开里有效。

## 2. 地基

快捷键按物理键匹配、修饰键实时生效、拖动中按 Esc 取消、剪贴板（复制、剪切、粘贴、原位粘贴、粘贴到这里、复制属性、复制为 PNG / SVG，⌘D 重复上次的偏移）已经做完，见 architecture.md 的"输入与快捷键""剪贴板"两节。剩下的几项本身用户感觉不到多少变化，但后面的右键菜单、快捷键、吸附、Alt 复制都要用到，先做。

### F-4 补齐命令

选择（父级、子级、同级、反选、按条件选）、锁定、隐藏、全部解锁、全部显示、拼合、创建或释放蒙版、键盘改大小、复制一份并挪动、缩放到选区、字号按档位加减已经做成命令（见 architecture.md"输入与快捷键"一节）。菜单还要用到、现在还没有的：

- **编辑**：复制为 CSS（UI-7）。
- **选择**：用了某个样式的对象（资源面板的右键菜单用）。
- **对象**：只显示这个；重命名（界面层打开改名框，⌘R）；用画框包起来（[UI-1](#ui-1-画框)）；移到某一页幻灯片。
- **画板 / 幻灯片**：调整顺序（移到某个位置、上移、下移）、设为幻灯片 / 取消幻灯片、隐藏幻灯片、适应内容大小、清除辅助线。
- **视图**：显示 / 隐藏标尺、辅助线、版面网格、像素网格，吸附的各项开关，隐藏界面。
- **图片**：替换图片、恢复原始比例、导出原图。

命令都在 `editor/src/commands/` 里按现有的分文件方式加，每个都带 `enabled` 和单元测试。

## 6. 选择和变换

⌘ 单击深选、回车 / ⇧回车选子级和父级、⇥ 选同级、悬停高亮、框选的修饰键、按条件选择、Shift 锁定 45°、Alt 拖动复制、Alt 从中心缩放、从四个角外侧旋转、键盘改大小和复制一份并挪动已经有了（见 architecture.md 的"输入与快捷键"一节）。还没有的：

### SEL-1 点选

- 在组里双击空白处，退回上一层。选中的是路径时回车进入锚点编辑（[PATH-1](#path-1-直接选择工具)）。

### SEL-2 框选

- 偏好里可以改成"整个框住才选"（现在框到一部分就选中，Illustrator 是这样，Sketch 两种都有）。

### SEL-5 缩放

- 拖过对边时翻转（现在的 `resizeBounds` 在对边处停住，不翻转）。
- 拖动时选区框下面显示"宽 × 高"，旋转时显示角度（[1.3](#13-反馈)）。
- **缩放工具（K）**：现在的缩放只改几何，描边、圆角、字号不变（architecture.md 里写的规则）。做 UI 时常常要"整体放大一倍"，连描边、字号、圆角、阴影都按比例变。缩放工具就是做这个的：拖控制柄或者在属性面板里输入比例，按比例改每个对象的几何和这些参数（不往变换矩阵里塞缩放，所以之后照样能改）。

### CORNER-1 顶点圆角

对应用户的第 3 条。

- **数据**：
  - 矩形：加可选的 `cornerRadii?: [左上, 右上, 右下, 左下]`。省略时四个角都是 `cornerRadius`，旧文件不变。
  - 路径、多边形：锚点 `Anchor` 加可选的 `radius?`，只对尖角起作用（两边控制柄都和锚点重合的锚点，或者两条边在这里不相切的锚点）。
  - 圆角样式：可选的 `cornerStyle?: 'round' | 'inverted' | 'chamfer'`（圆角、反向圆角、倒角，Illustrator 的三种），省略是圆角。
  - 平滑度：可选的 `cornerSmoothing?`（0 到 1），像 iOS 图标那样的连续曲率圆角，UI 设计常用（Figma 叫 corner smoothing，0.6 接近 iOS）。
  - 都是可选字段，`validate.ts` 跟着更新；组件的覆盖按属性名记，自动支持。
- **几何放在 core 里**：新文件 `core/src/corners.ts`，把"带圆角的矩形、带圆角半径的锚点"换成不带圆角的普通锚点（圆弧用三次曲线近似，误差很小）。渲染器的 `nodes/shapes.ts` 和 `buildPath` 用它，所以画布、命中、导出 PDF / SVG、轮廓化描边、偏移路径、布尔运算全部一致，不用各自处理。导出 SVG 时四个角相同、没有平滑度的矩形仍然写成 `<rect rx>`，其余写成路径。
  - 半径太大时按两条相邻边能放下的长度收缩；相邻两个角加起来超过边长时按比例分。
  - 第一步只处理两边都是直线的角；一边或两边是曲线的角（Illustrator 支持）放到第二步，要在曲线上按弧长找切点再拆开。
- **画布上的操作**：
  - 只选中一个矩形、多边形或路径，而且它在屏幕上够大（每条边超过 30 像素左右）时，每个能加圆角的角里面显示一个小圆点控件。控件放在圆角的圆心位置；半径是 0 时放在离角 12 屏幕像素、角平分线上的位置。
  - 拖控件：所有角一起变（Illustrator、Figma 都是这样，最常用）；按住 Alt 拖：只改这一个角。半径按鼠标在角平分线上的位移换算（圆心沿平分线移动 d，半径变 d × sin(角度 / 2)），用相对位移算，按下时不会跳。
  - 拖动时鼠标旁显示半径；到了最大值时那段圆弧变红（Illustrator 的提示）。默认取整。
  - Alt 单击控件：在圆角、反向圆角、倒角之间轮换（Illustrator 的习惯）。双击控件：弹出一个小面板，输入半径、选样式、调平滑度。
  - 直接选择工具里：控件只出现在选中的锚点上，拖它改选中的这几个锚点。
  - 点中的优先级：控件在形状里面，缩放控制柄在外框的角上；两者离得近时控件优先（离控件 6 像素以内）。在控件上按下不会开始移动对象。
  - 视图菜单里可以关掉"圆角控件"。多选时不显示，用属性面板改。
- **属性面板**：圆角一栏一个数字框，旁边一个"四个角分开"的按钮，展开成四个框（值不同时单个框显示"混合"）；样式三选一；平滑度滑块。路径在锚点编辑里时，显示选中锚点的半径。
- **缩放时**：圆角半径保持文档单位不变（现在的规则"缩放只改几何，圆角不变形"），超过时按上面的规则收缩；缩放工具 K 按比例缩放半径。
- **涉及**：`core/src/model.ts`、`validate.ts`、新的 `core/src/corners.ts`，`renderer/src/nodes/shapes.ts`、`renderer/src/svg.ts`，`editor/src/overlay.ts`、`tools/select.ts`、新的圆角手柄文件（仿照 `fill-handles.ts`），`apps/web/src/panels/TransformPanel.tsx`。
- **怎么算做完**：单元测试检查 `corners.ts` 的几何（四个角各不相同、半径过大收缩、三种样式、平滑度为 0 时等于普通圆角）；在 Node 里把画布和导出的 PDF、SVG 逐像素比较；浏览器里实测拖控件、Alt 单角、Alt 单击换样式、最大值变红、转过角度和翻转过的矩形。

## 11. UI 界面设计

对应用户的第 6 条。现有的组件、颜色和文字样式是基础，还缺下面这些。顺序就是建议的做法顺序。

### UI-1 画框

- **为什么要新类型**：画板是顶层的（它同时是幻灯片的一页，`slides()` 只列顶层画板），不能嵌套；编组没有自己的外观、不裁剪。做界面时一屏里面套着卡片、卡片里套着按钮，每层都要有背景、圆角、裁剪，以后还要自动布局。所以新加一个 `frame` 节点类型，而不是让画板能嵌套（那样幻灯片的很多规则要改）。
- **画框是什么**：有自己的大小、填充、描边、圆角（用 [CORNER-1](#corner-1-顶点圆角) 的字段）、是否裁剪内容（默认裁剪）、效果（[UI-4](#ui-4-阴影和模糊)）、自动布局（[UI-3](#ui-3-自动布局)）、版面网格（[UI-5](#ui-5-版面网格)）的容器，可以放在画板里，也可以互相嵌套。
- **操作**：画板工具 F 在画板里拖出来；选中几个对象按 ⌥⌘G "用画框包起来"（画框正好框住它们）。点画框里的空白处选中画框（和点编组的空白处不一样，编组没有空白处）。
- **渲染和导出**：先画自己的填充，再画子节点（裁剪时按自己的轮廓裁），最后画描边。导出 PDF 时裁剪写成裁剪路径，SVG 写成 `<clipPath>`，和现在的形状蒙版是同一套写法；播放器当成一个图层或者一组图层（和编组一样处理）。
- **涉及**：`core/src/model.ts`（`NodeTypeMap` 加 `frame`）、`validate.ts`、新的 `renderer/src/nodes/frame.ts`、`pdf.ts`、`svg.ts`、`editor` 的命中和选择、图层图标。

### UI-2 约束

- **要做**：画框、画板改大小时，里面的对象按约束跟着变。水平方向：靠左、靠右、左右都靠（拉伸）、居中、按比例；垂直方向：靠上、靠下、上下都靠、居中、按比例。
- **数据**：`BaseNode.constraints?: { h, v }`，省略等于靠左靠上，也就是现在的行为（`resize.ts` 里写着"画板只改自己的大小，里面的内容不跟着缩放"），旧文件不变。
- **操作**：属性面板的位置与大小里，父节点是画框或画板时出现约束的小图（一个方框，四条边和中间的十字可以点）。改画框大小时按住 ⌘ 暂时不按约束（里面的东西不动）。
- **顺带解决组件的问题**：[PROD-1](backlog.md#prod-1-组件与样式的补充) 里写着实例只能整体缩放、非等比拉伸时文字被拉扁。有了约束，实例改大小可以选"按约束"：底板拉伸、文字不变。实例的缩放方式在组件面板里切换（整体缩放 / 按约束），默认保持现在的整体缩放。
- **涉及**：`core/src/model.ts`、`validate.ts`、`editor/src/resize.ts`（`scaleContent` 的画板分支和画框分支）。

### UI-3 自动布局

- **要做**：画框里的子对象按方向自动排列。参数：方向（横、竖）、间距、内边距（上右下左）、对齐（主轴、交叉轴）、每个方向上画框自己的尺寸方式（固定、包住内容、填满父级）、子对象的尺寸方式（固定、填满）、子对象可以"不参与自动布局"（绝对定位）。换行放到第二步。
- **数据**：`FrameNode.layout?`，子对象的 `layoutSizing?`、`layoutIgnore?`。
- **计算结果写回节点**：算出来的位置和大小直接写进子对象的 `transform` 和 `size`，所以渲染、导出、播放器、视频全部不用认识自动布局（和组件的副本、样式的值是同一个思路）。
- **在整理器里算**：现在的整理器在 core 里，管样式和组件的同步（`core/src/store.ts`）。自动布局要量文字的大小，量文字要渲染器，所以要在 editor 里挂一个整理器：
  - 先让整理器的钩子支持多个、按顺序跑：样式 → 组件 → 自动布局（实例里的副本要先补齐再排）。
  - 实例里的自动布局：主组件里的文字改长了，实例照着同步；实例里的文字被覆盖得更长时，实例要自己再排一次，排出来的位置不能被当成"用户改了"记成覆盖。组件同步要认得自动布局写的属性。
  - 字体晚到（异步加载完）时文字大小会变，要重新排一次，而且不能进撤销历史。存储要有一种"不记历史的整理"。这两点是这一项最难的地方，动手前先做个小原型。
- **算法**：纯函数放在 core（新文件 `core/src/auto-layout.ts`，`layouts.ts` 已经被幻灯片版式占用了），传入一个量尺寸的回调，在 Node 里用固定尺寸测。
- **操作**：⇧A 给选中的画框加自动布局（选中的是几个对象时先包一个画框）。画布上：在自动布局的画框里拖子对象是调整顺序（显示插入条），拖出画框就离开布局；鼠标停在画框上时间距和内边距区域显示成粉色，可以直接拖。属性面板：方向、间距、内边距、3 × 3 的对齐小图、宽高的尺寸方式。

### UI-4 阴影和模糊

- **要做**：投影、内阴影、图层模糊、背景模糊，可以叠好几个。数据 `effects?: Effect[]`，放在形状、文本、编组、画框上。
- **渲染**：投影用 Skia 的图像滤镜；内阴影自己合成（反转轮廓、模糊、裁回形状里）；背景模糊用 `saveLayer` 的背景滤镜参数（CanvasKit 支持，要实测性能）。
- **导出**：SVG 写 `<filter>`（`feGaussianBlur`、`feOffset`、`feFlood`、`feComposite`）；PDF 没有模糊，阴影烤成图片放在矢量形状下面（`bake.ts` 的做法），背景模糊整块烤成图片；播放器用 SVG 滤镜，背景模糊在网页里可以用 CSS 的 `backdrop-filter`；视频的图层本来就是图片。
- **注意**：阴影会让对象画出来的范围变大，`drawnBounds`、场景缓存的视口裁剪、导出 PNG 的范围都要算上。和画布逐像素比较时阴影的模糊要量化差异。

### UI-5 版面网格

- 画框和画板上可以加列网格、行网格、方格网格：数量、宽度（或拉伸）、间隔、边距、颜色。⇧G 开关显示。
- 吸附到列和行的边（[SNAP-1](#snap-1-吸附的补充)）。
- 演示稿、海报也用得上（比如 12 列网格排版）。数据 `layoutGrids?`，导出不画。

### UI-6 原型

- **要做**：把画板（屏幕）连起来，点某个按钮跳到另一个屏幕，带过渡效果，在演示模式里点着玩，导出可以点的网页。
- **和现有的播放器高度重合**：播放器已经能逐页播放、做五种切换，其中"平滑"就是 Figma 的"智能动画"（按血缘配对补间）。复制一个屏幕再改就能平滑过渡，这一点已经有了。原型只需要：
  - 数据：对象上加 `interactions?`：触发方式（点击，以后加悬停、拖动）、动作（跳到某个画板、返回上一个）、过渡（用现有的 `SlideTransition`）。
  - 编辑：属性栏加一个"原型"页；选中对象后从它右边拖出一根线连到目标画板（Figma 的连线），或者在下拉里选。
  - 播放：编译时给页面加上热区和目标，播放器的单击不再是"下一步"，而是看点中了哪个热区。播放器的源码要保持完全不引用外部变量（AGENTS.md 里的约定）。
- 以后：滚动区域、固定在顶部的元素、悬停状态。

### UI-7 标注和交付

- **检查**：属性栏加一个"检查"页（只读）：选中对象的尺寸、位置、颜色、圆角、字体、阴影，写成 CSS（以后加 iOS、Android 的写法），可以一键复制。
- **测距**：Alt 悬停测距（已有）。
- **复制为 CSS**：右键菜单里，和已有的"复制为 SVG"放在一起。
- **导出设置**：对象和画框上可以加导出设置（1x、2x、3x，PNG、JPEG、SVG、PDF，文件名后缀），存进文档；文件菜单"导出…"列出所有设置了导出的对象，一次全部导出成 ZIP。顺带解决 backlog 第 7 节里"导出 PNG 只能一个对象"的问题。

### UI-8 素材和起步

- 新建文档对话框的预设里加"界面"一类：手机（393 × 852）、安卓（360 × 800）、平板（820 × 1180）、桌面（1440 × 1024）、网页（1920 × 1080）。加在模板功能的预设表里（`apps/web/src/templates/presets.ts`），不是幻灯片（`slides: false`）。
- 图标库：资源面板加一页图标，搜索后拖到画布上变成路径。项目已经依赖 lucide（界面图标），它是 ISC 许可，可以直接用；要加别的图标库先核实许可能不能商用。
- 界面模板：登录页、设置页、卡片列表等，走模板库。

### UI-9 以后

- 组件的变体和组件属性（一个按钮组件有"主要 / 次要""正常 / 禁用"几种状态）。
- 变量（设计令牌）：颜色、数字变量，可以有亮暗两套值，切换整份设计的主题。现有的颜色样式可以升级过去。
- 在手机上预览原型。

## 13. 建议的顺序

每一步是一个分支（`feature/xxx`），单独可以用。和 backlog 里已有的几项有交叉：[EDIT-4](backlog.md#edit-4-段落样式的补充)、[PROD-1](backlog.md#prod-1-组件与样式的补充) 的快捷键问题（要按 `event.code` 匹配）已经解决；PROD-1 的约束和自动布局、[PROD-2](backlog.md#prod-2-模板的补充) 的母版都依赖 UI-2 的约束；PROD-2 里"画布视图里新建画板"由 TOOL-1 的画板工具和画布的右键菜单解决；[ANIM-1](backlog.md#anim-1-动作路径的补充) 的锚点编辑和 PATH-1 一起做。

## 14. 验证

- 纯逻辑放在不依赖浏览器的地方，用单元测试在 Node 里测：剪贴板的序列化和放置规则、吸附的查找、面板布局的变换、圆角几何、自动布局的算法、快捷键匹配。
- 几何和渲染相关的（圆角、画框的裁剪、阴影）照现有做法和导出的 PDF、SVG 逐像素比较，写明差异有多大、差在哪。
- 右键菜单、面板拖动、吸附、Alt 复制在浏览器里用真实的鼠标和键盘事件实测（面板拖动用指针事件实现，自动化工具能驱动）。开发版里 `window.shiba` 是编辑器实例，可以在控制台里造数据。
- 快捷键和剪贴板在 Chrome、Safari、Firefox 里表现不一样的地方多，这几项至少三个浏览器各试一次；只在 Chromium 内核里验证过的，在 architecture.md 里写明。
