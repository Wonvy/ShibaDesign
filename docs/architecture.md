# ShibaDesign 方案与架构

定稿日期：2026-11-27。本文是产品范围和技术架构的依据；代码结构与扩展方式见根目录的 `README.md`。

## 1. 定位

基于 Web 的跨平台设计工具，把图片设计、演示、动画和轻量修图合在一个软件里。先做单机，实时协同放到公测之后。

### 不做（至少前两年）

- PS 级像素绘画：16/32 位、通道、智能对象。

## 3. 统一文档模型：画板即幻灯片

不做两套数据，只做两种视图。

- **自由画布视图**：无限画布，所有画板自由摆放，画板外可以放散落的对象。
- **幻灯片视图**：缩略图条按顺序排列，主区域一次只显示一个画板。
- 画板带 `deck` 字段就是一页幻灯片，不带就是普通画板。同一个文件可以既有海报又有演示稿。
- 切换视图只改相机和界面，不转换数据。

节点是不可变的普通对象，存在一张以 id 为键的表里。树结构用 `parent` + `index`（分数索引）表达，为以后接入协同预留。每个节点有 `lineageId`，复制幻灯片时保留，"平滑"切换靠它在前后两页之间配对。

节点类型：`page`、`artboard`、`rect`、`ellipse`、`path`、`boolean`、`text`、`group`（已实现）；`instance`（待做）。图片不是节点类型，而是形状的一种填充。

## 6. 子系统设计要点

### 渲染与混合模式

- 16 种标准混合模式 Skia 原生支持，与 CSS `mix-blend-mode` 和 PDF 混合模式一一对应。PS 独有的 11 种以后用自定义着色器做。
- 组分两种：穿透（默认）和隔离（设了混合模式或不透明度时开离屏层）。
- 场景缓存：文档不变时把整个场景录成一张 Skia 图片，平移缩放直接回放，Skia 的空间索引自动跳过视口外的内容。文档变化的那一帧走逐节点绘制加视口裁剪。

### 对象操作

- **对齐与分布**：纯函数，输入外接矩形，输出位移。多选时以选区为基准，单选时以所在画板为基准。已有六种对齐、等间距分布、等中心距分布。待做：关键对象、视觉边界、锚点级对齐、间距手柄。
- **布尔运算**：非破坏性的"布尔组"节点，子节点保持可编辑，结果由 Skia PathOps 实时计算。已有联集、减去顶层、交集、排除，可嵌套。待做：拼合为普通路径、分割、修边、PathOps 失败时回退到 Clipper2。
- **旋转**：拖选区框上方的旋转手柄，或在属性面板里输入角度；按住 Shift 以 15° 为步长。多个对象绕选区中心一起转。画板不能旋转。
- **缩放**：只选一个对象时，选区框跟着对象一起倾斜，缩放沿对象自己的方向进行，没被拖动的那一侧在画布上不动，对任意角度都精确。多选时缩放整体外接矩形；其中转过角度的对象无法在不变形的前提下做非等比缩放，按它自己的方向近似换算宽高。缩放只改几何，不往变换矩阵里塞缩放，所以描边粗细、圆角、字号都不会变形。
- **翻转**：水平或垂直，以选区中心为轴。
- **编组**：把对象当成一个整体来选择、移动、旋转、缩放；组可以嵌套，可以设不透明度和混合模式。默认点中组里的对象选的是整组；双击进入组后，单击选的是成员，选到组外的东西就算离开。取消编组后成员留在原位，组的旋转留在每个成员身上。
- 其他已有：移动、层序、复制、删除、方向键微移、跨画板拖动自动换归属。待做：蒙版、轮廓化描边、偏移路径、双击进入布尔组。

### 中英文

- 界面文字全部走语言包。内核只返回数据，图层默认名（"矩形 1"）由界面按当前语言生成，不存进文件。
- 语言包可导出为 JSON，用户翻译后导入即成为一门新语言；缺失的条目回退到英文。导入的内容按不可信数据校验。
- 内容混排：中西文字体分设、行高统一已实现；中英文间自动间距、标点挤压、行首行尾禁则待做。

### 文本

- **数据**：文本节点存内容、样式（中西文字体、字号、字重、行高、字距）、对齐和宽度模式。自动宽度只在换行符处折行；固定宽度自动折行。高度始终由排版决定。目前整段共用一个样式，字符级样式待做。
- **字体**：字体文件随应用发布，不依赖外部字体服务。每个家族按 Unicode 区间切成很多小文件，排版时只加载用到的那几个。常用汉字集中在七八个分片里，每个约 30KB。内置 Inter 和思源黑体，各有常规和粗体。
- **排版**：用 SkParagraph。每个字符由字体列表里第一个包含它的家族负责，所以西文走西文字体，中文走中文字体。用"支柱"把每行强制成 字号 × 行高，否则中英文混排的行会比纯中文的行高出几个像素。
- **编辑**：文字画在画布上，键盘输入交给一个看不见的 `<textarea>`。它负责输入法、组合键、剪贴板和左右移动光标，我们把它的内容和选区同步到文档，自己在画布上画光标和选区。输入框始终跟着光标移动，输入法的候选窗才会出现在正确的位置。
- 上下方向键由我们接管，按真实排版计算；编辑中的撤销走文档的历史，不用输入框自带的。
- 一段连续输入是一步撤销；新建文本后什么都没写就离开，不在文档和撤销历史里留痕迹。
- 待做：字符级样式、段落间距与缩进、列表、Home / End 按视觉行移动、表情符号字体、竖排、沿路径排列、文字转轮廓。

### 打开 PDF 并编辑

按转换式设计：打开时把页面内容转成自己的可编辑对象，改完导出新的 PDF，不覆盖原文件。

- 每页变成一个画板。
- 路径、图片、裁剪、透明度组、线性和径向渐变转成原生对象；网格渐变和平铺图案栅格化；表单和批注按外观压平；CMYK 转 sRGB。
- 文本延迟转换：打开时是用内嵌字体原样显示的"保真文本"，用户第一次编辑某段时才重建段落、匹配字体。
- 导入器分两层：解析库 → 自己的中间表示 → 节点，以后换解析库不影响后半段。
- 转换后与 PDF 引擎直接渲染的位图做像素对比，差异大的页面提示用户。
- 导出需要矢量、文字可搜索的 PDF。首选自己编译带 PDF 后端的 Skia，不行就基于 pdf-lib 自写。

### 动画

PPT 式的幻灯片动画，用 HTML5 实现。

- 每页有一个页面切换效果和一张按顺序排列的动画列表。每条动画有类别（进入、强调、退出、动作路径）、效果、触发方式（单击时、与上一动画同时、上一动画之后）、时长、延迟、缓动。
- 每个效果是一个函数：输入元素位置、页面尺寸和参数，输出标准关键帧。
- HTML5 播放器是独立的小型运行时，用 Web Animations API 驱动。编辑器内预览、全屏演示、分享链接、导出的 HTML 文件都用它。
- 编辑在 Skia 画布上进行，播放时每个元素转成一个 DOM 图层：文本是真实文字，矢量是内联 SVG，图片调整预先烘焙，超出浏览器能力的效果由 Skia 渲染成位图。
- "平滑"切换：按 `lineageId` 在前后两页间配对，对位置、大小、旋转、透明度、颜色、圆角做插值；配不上的淡入淡出。
- 自由关键帧时间轴（After Effects 式）放到后期，与动画列表共用同一种关键帧数据。

### 图片

- **图片是填充，不是节点**：图片作为形状的一种填充存在，所以矩形、椭圆、钢笔路径、布尔组都天然是图片的蒙版。放一张图片到画布上，得到的是一个用它作填充的矩形。
- **铺放方式**：铺满（保持比例，裁掉多余）、适应（完整显示，留空处透明）、拉伸。
- **资源库**：图片字节存在资源库里，按内容的 SHA-256 寻址。同一张图片导入多次只存一份；节点只记资源 id。
- **导入**：工具栏按钮、拖进画布、粘贴。渲染引擎能直接解码 PNG、JPEG、GIF、BMP；其他格式（WebP、AVIF 等）由浏览器转成 PNG 再存。
- **大图**：长边超过 4096 像素的图片在导入时缩小。解码后的图片整张放在内存和显存里，不限制的话几张相机原图就能拖垮画布。这是临时做法，会损失原图分辨率；正式方案是保留原图、编辑时用缩小的代理图、导出时再用原图。
- **调整**：非破坏性，只存一组参数，原图不动。调色有亮度、对比度、饱和度、色温、色调、色相，合成一个颜色矩阵交给 GPU；其中亮度、对比度、饱和度、色相的算法与 CSS 滤镜的定义一致，以后导出成网页可以直接用 CSS 实现。模糊只作用于图片内容，形状的边缘保持清晰。
- **画面内缩放与平移**：在铺放方式之上再把图片放大、移动它在形状里的位置，相当于简单的裁剪。
- 待做：在画布上直接拖动图片来裁剪、曲线、锐化、LUT 滤镜预设、本地抠图、在 Worker 里解码。抠图模型要选可商用许可的。

### 文件格式与存储

- **.shiba 文件**是一个 ZIP 包：`manifest.json`（格式标识、版本、资源清单）、`document.json`（节点表）、`assets/<内容哈希>.<扩展名>`（图片）。图片已经压缩过，原样存入不再压缩。把扩展名改成 .zip 就能用普通工具解开。
- 保存时只写入文档实际引用的图片，撤销掉或换掉的图片不占体积。
- **打开文件按不可信输入处理**：只读取认识的条目，限制解压后的总大小，文档结构要过校验（字段类型、数值有限、父子关系不成环）。校验不通过就拒绝打开，当前文档不受影响。不认识的节点类型会放行，方便旧版本打开新文件。
- **保存方式**：浏览器支持文件系统访问接口时（Chrome、Edge）直接写回用户选的文件；不支持时（Safari、Firefox）退回成下载。
- **本地草稿**：正在编辑的文档自动存在 IndexedDB 里，刷新或意外关闭后能接着做。文档每次修改后重写，图片只在第一次出现时写一次。草稿不等于保存文件。
- **导出 PNG**：导出当前画板或选中的单个对象，支持 1 倍和 2 倍，单边上限 8192 像素。导出前会等文本用到的字体全部加载完。
- 待做：SVG 导出、JPEG 导出（渲染引擎的默认构建不带 JPEG 编码器）、文件内嵌缩略图、OPFS 存储。

## 8. 主要风险

1. **文本引擎**：中文输入法、字体回退、大字体按需加载是最容易低估的部分。
2. **PDF 文本重建**：多栏、表格、缺字体这类长尾问题会持续很久。
3. **布尔运算稳健性**：PathOps 的失败情况必须有回退路径和回归测试集。
4. **范围**：每个阶段的验收标准当作硬边界，否则公测时间会一直后移。
5. **CanvasKit 体积**：WASM 文件 7.3MB，gzip 后约 3MB，首屏要做加载优化。
6. **CanvasKit 的类型声明与实际不完全一致**：0.42 版声明了 `path.makeCombined`，但默认构建里没有。用到新接口时要实测。
7. **平板内存**：iPad Safari 对大画布和大图的内存限制很紧。
