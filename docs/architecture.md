# ShibaDesign 方案与架构

定稿日期：2026-11-27。本文是产品范围和技术架构的依据；代码结构与扩展方式见根目录的 `README.md`，还没做的功能汇总在 [backlog.md](backlog.md)。

## 1. 定位

基于 Web 的跨平台设计工具，把图片设计、演示、动画和轻量修图合在一个软件里。先做单机，实时协同放到公测之后。

### 不做（至少前两年）

- PS 级像素绘画：16/32 位、通道、智能对象。
- Acrobat 式的 PDF 原位编辑：表单、签名、书签、无障碍标签不保留。
- CMYK 印前全流程和印刷级色彩保真。
- 与 AI / PPTX 的完整双向保真。

## 3. 统一文档模型：画板即幻灯片

不做两套数据，只做两种视图。

- **自由画布视图**：无限画布，所有画板自由摆放，画板外可以放散落的对象。
- **幻灯片视图**：缩略图条按顺序排列，主区域一次只显示一个画板。
- 画板带 `deck` 字段就是一页幻灯片，不带就是普通画板。同一个文件可以既有海报又有演示稿。
- 切换视图只改相机和界面，不转换数据。

节点是不可变的普通对象，存在一张以 id 为键的表里。树结构用 `parent` + `index`（分数索引）表达，为以后接入协同预留。每个节点有 `lineageId`，复制幻灯片时保留，"平滑"切换靠它在前后两页之间配对。

节点类型：`page`、`artboard`、`rect`、`ellipse`、`path`、`boolean`、`text`、`group`。图片不是节点类型，而是形状的一种填充。组件和实例也不是单独的节点类型，而是带标记的编组（见"组件与样式"一节）：原计划的 `instance` 节点类型没有做，这样渲染、导出、选中这些按编组处理的代码不用改。

## 6. 子系统设计要点

### 渲染与混合模式

- 16 种标准混合模式 Skia 原生支持，与 CSS `mix-blend-mode` 和 PDF 混合模式一一对应。PS 独有的 11 种以后用自定义着色器做。
- 组分两种：穿透（默认）和隔离（设了混合模式或不透明度时开离屏层）。
- 场景缓存：文档不变时把整个场景录成一张 Skia 图片，平移缩放直接回放，Skia 的空间索引自动跳过视口外的内容。文档变化的那一帧走逐节点绘制加视口裁剪。

### 对象操作

- **对齐与分布**：纯函数，输入外接矩形，输出位移。多选时以选区为基准，单选时以所在画板为基准。已有六种对齐、等间距分布、等中心距分布。待做：关键对象、视觉边界、锚点级对齐、间距手柄。
- **布尔运算**：非破坏性的"布尔组"节点，子节点保持可编辑，结果由 Skia PathOps 实时计算。已有联集、减去顶层、交集、排除，可嵌套。拼合（⌘E，`path.flatten`）把布尔组换成运算结果的钢笔路径（运算对象去掉），矩形、椭圆也能这样转成路径；填充、描边不变，id 和血缘沿用（和轮廓化描边一样用 `replaceNode`）。待做：分割、修边、PathOps 失败时回退到 Clipper2。
- **旋转**：拖选区框上方的旋转手柄，或在属性面板里输入角度；按住 Shift 以 15° 为步长。多个对象绕选区中心一起转。画板不能旋转。
- **缩放**：只选一个对象时，选区框跟着对象一起倾斜，缩放沿对象自己的方向进行，没被拖动的那一侧在画布上不动，对任意角度都精确。多选时缩放整体外接矩形；其中转过角度的对象无法在不变形的前提下做非等比缩放，按它自己的方向近似换算宽高。缩放只改几何，不往变换矩阵里塞缩放，所以描边粗细、圆角、字号都不会变形。
- **翻转**：水平或垂直，以选区中心为轴。
- **编组**：把对象当成一个整体来选择、移动、旋转、缩放；组可以嵌套，可以设不透明度和混合模式。默认点中组里的对象选的是整组；双击进入组后，单击选的是成员，选到组外的东西就算离开。取消编组后成员留在原位，组的旋转留在每个成员身上。
- **蒙版**：编组可以设成蒙版组，组里最上面的对象当蒙版，遮住其余的对象，自己不画出来。选两个以上的对象点"创建蒙版"，最上面那个就成了蒙版——形状盖在图片上面再点一下，图片就被裁成这个形状，和 Illustrator 的剪切蒙版一样。三种模式：
  - 形状：按蒙版的轮廓裁剪，不看颜色。纯矢量，导出 PDF 时是裁剪路径。普通形状（矩形、椭圆、钢笔路径、布尔组）新建时默认用它。
  - 透明度：按蒙版画出来的不透明程度遮，半透明、渐变、文字、带透明的图片都可以当蒙版。文字、编组、图片新建时默认用它；形状模式遇到没有轮廓可用的蒙版（文字、编组）时也按它来。
  - 亮度：按蒙版的明暗遮，白色显示、黑色隐藏。
  - 渲染：形状模式直接裁剪；另外两种把内容画进一个单独的层，再把蒙版用"只保留重叠部分"的混合方式盖上去，亮度模式先把亮度换成透明度。
  - 蒙版组的范围就是蒙版的范围，选区框、对齐都按它；画布上只有蒙版范围里的内容点得中，蒙版本身在图层列表里选。释放蒙版后组还在，蒙版变回普通对象。
  - 移动蒙版里的内容：双击蒙版组选中鼠标下面的内容，拖动它，蒙版不动。选中的是蒙版组里的内容时，画布上用虚线画出蒙版的轮廓，看得出露出来的范围。
- **描边**：居中画在轮廓上，可以设虚线（实线段和空白交替的长度、起始偏移）、端点（平头、圆头、方头）、拐角（尖角、圆角、斜角），都是可选的字段（`core/src/stroke.ts`），省略时是平头、尖角、实线，旧文件不受影响。外观面板有实线、虚线、点线三个预设（按线宽算间隔，点线是长度为 0 的实线段加圆头），也可以自己输入间隔；用预设时改线宽，间隔跟着变。渲染用 Skia 的虚线效果，导出 PDF 写 `d`、`J`、`j` 指令，导出 SVG 写 `stroke-dasharray` 等属性；虚线从路径的起点开始排，所以有虚线时矩形、椭圆在 SVG 里写成路径，起点和画布一致。打开 PDF 时虚线、端点、拐角原样还原。
- **在画布上调整填充**：双击填了渐变的形状（或者画板的空白处，背景是渐变时），或者点渐变编辑器里的按钮，进入调整渐变：缩放、旋转控制柄换成渐变的起点、终点手柄（填着首尾色标的颜色），径向渐变还有一个调压扁比例的手柄。拖起点、终点改渐变，径向渐变拖圆心整个挪；按住 Shift 方向按 45° 吸附。双击填了图片的形状（或者图片面板里的按钮），进入调整图片：画出整张图片的范围，在形状里拖动是移动图片，拖四个角是缩放（1 到 4 倍，中心尽量不动），改的是画面内的缩放平移。按 Esc、换选区、换工具退出。渐变的起点终点常常正好落在选区框的角上、边的中点上，所以这是一个单独的状态（`editor/src/fill-handles.ts`）。
- **生成路径**（`editor/src/commands/path.ts`，几何运算在 `renderer/src/path-ops.ts`）：属性面板的"路径"一栏，结果都是普通的钢笔路径，之后可以随便改。
  - 轮廓化描边：把描边变成一块按描边颜色填充的路径，端点、拐角、虚线、斜接限制都和画布上画的一样。没有填充的形状直接换成这条路径；有填充的换成一个编组，下面是去掉描边的原形状，上面是描边变成的路径（和 Illustrator 一样）；布尔组的运算对象跟着填充部分走。虚线是自己按 Skia 虚线效果（SkDashPath）的规则拆段的：起始偏移取余、每个子路径从头数、闭合的子路径把开头那段实线挪到最后和末段连成一笔、长度为 0 的实线段留成一个点；再用 Skia 的描边器描、用 PathOps 合并成互不重叠的轮廓。Skia 的类型声明里有 `makeSimplified`，0.42 的默认构建里没有，和一条空路径求并集是一样的效果。
  - 偏移路径：对话框里填距离和拐角。做法是用 2 倍距离的描边和原形状合并（外扩）或者相减（内缩）；没闭合的路径按填充时的样子算。新路径照搬原来的填充和描边，原形状保留：外扩的放在它下面，内缩的放在它上面。缩没了的什么都不生成。
  - 文字转轮廓：文字画出来的字变成路径，每种颜色一条，好几种颜色时放进一个编组。字形轮廓从字体文件里读，按排版结果摆好（和导出 SVG 时"转成轮廓"是同一份代码）；模拟粗体、下划线、删除线用 PathOps 合并进来；从 PDF 导入、没改过的文字直接用原文件的字形。要取字体文件，是异步的，代码单独打包（`@shiba/renderer/text-outline`）。新路径的名字默认是文字的第一行。
  - 轮廓化描边和文字转轮廓是"换掉原来的对象"：新对象沿用原来的 id、lineageId、名字、位置、不透明度、混合模式，所以加在它上面的动画、和别的幻灯片之间的平滑切换都还接得上；整个替换是一步撤销。
  - Skia 路径存回文档：先转成路径数据，再转成锚点（`core/src/path-data.ts`，原来是打开 PDF 用的，挪进了 core），锚点以外框左上角为原点。PathOps 算出来的路径按奇偶规则填充，内外轮廓方向不一定相反，所以填充规则原样带上。
  - 验证：在 Node 里把画布上画的和转出来的路径逐像素比较（2 倍）。轮廓化描边（实线、圆头圆角、虚线、多段虚线加负的起始偏移、点线，转过角度的圆角矩形、椭圆、开放的曲线）差异明显的像素不到 0.2%，最大差值小于 224/255；有填充的半透明描边编组后、布尔组的描边也一样。文字转轮廓（中英文、几种颜色、真粗体和模拟粗体、下划线、删除线）不到 0.5%，PDF 导入的文字完全一样。在 Chrome 里实测：带虚线的圆角矩形转完差 4 个像素（共 368 万个），中英文混排的文字差 0.066%，都在边缘的抗锯齿上。
  - 画布上的虚线在曲线上的位置要量弧长，Skia 按当前的缩放倍数量；转出来的按 4 倍的精度量，所以沿着圆角走一段以后，和画布上会有零点几个单位的出入，放大看时画布上的点会稍微挪一点。
- 其他已有：移动、层序、复制、删除、方向键微移、跨画板拖动自动换归属（只对直接放在画板、页面上的对象；编组、蒙版组里的成员挪动后留在组里）。待做：双击进入布尔组。

### 输入与快捷键

鼠标、键盘事件由 `editor/src/input.ts` 翻译成工具调用和命令；快捷键表在 `editor/src/keymap.ts`。操作和界面的整体改版方案见 [interaction-plan.md](interaction-plan.md)。

- **快捷键按物理键匹配**：字母和数字按 `event.code` 认（`KeyK` → `k`、`Digit1` → `1`），标点、方向键、功能键仍按 `event.key`。Mac 上按住 Option 时 `event.key` 是别的字符（⌥K 是 `˚`），Shift 加数字在不同键盘布局下也不一样（美式键盘 Shift+1 是 `!`），按 `event.key` 配不上；原来"适应画面"只好写成 `shift+!`，现在写 `shift+1`。代价是法语 AZERTY 这类布局按的是键的位置，不是键帽上的字（Figma 也是这样取舍的）。没有 `code` 的事件（模拟出来的、某些虚拟键盘）退回 `event.key`。
- **显示**：`apps/web/src/ui/shortcut.ts` 把 `mod+alt+k` 写成 Mac 上的 `⌥⌘K`（修饰键顺序和系统菜单一样是 ⌥⇧⌘）、别的系统上的 `Ctrl+Alt+K`。顶栏、文件菜单、对齐和文本面板原来各写了一份转换（顶栏直接转大写，显示成"MOD+SHIFT+Z"），都换成它。
- **修饰键实时生效**：原来只在鼠标移动时读修饰键，拖到一半按下 Shift 要再动一下鼠标才锁定。现在输入控制器记着最后一次的指针位置，拖动中按下或松开 Shift、Alt、⌘、Ctrl 时，用新的修饰键状态再给工具发一次移动。
- **拖动中按 Esc 取消**：工具多了 `onCancel`，按 Esc 或者窗口失去焦点（拖到一半切到别的程序，松手事件可能收不到）时调用，之后这次拖动的松手不再交给工具。选择工具撤回移动、缩放、旋转、拖渐变或图片、拖动作路径的改动，框选换回按下鼠标之前的选区；形状工具撤掉画了一半的形状；钢笔撤掉这次单击放下的锚点；文本工具不建文本框。撤回靠存储新加的 `abandon(mergeKey)`：拖动的事务都带同一个合并键，它把这一步整个换回之前的快照，从撤销历史里拿掉，也不放进重做；最上面那一步不是它或者已经封口时什么都不做。
- **快捷键表**（`DEFAULT_BINDINGS`）：除了原来的工具、撤销、删除、层序、翻转、缩放，现在有：选子级 / 父级（↵ / ⇧↵，选中文本时回车开始编辑）、下一个 / 上一个同级（⇥ / ⇧⇥）、⌘ 方向键改大小（改右边和下边，⇧ 是 10）、⌥ 方向键复制一份并挪动、对齐（⌥A / ⌥H / ⌥D / ⌥W / ⌥V / ⌥S，和 Figma 一样）、分布（⇧⌥H / ⇧⌥V）、创建或释放蒙版（⌥⌘M）、布尔运算（⇧⌥U / S / I / E）、拼合（⌘E）、轮廓化描边（⌥⌘O）、文字转轮廓（⇧⌘O）、创建组件 / 分离实例（⌥⌘K / ⌥⌘B）、锁定 / 隐藏（⇧⌘L / ⇧⌘H）、复制属性 / 粘贴属性（⌥⌘C / ⌥⌘V）、复制为 PNG（⇧⌘C）、字号按档位加减（⇧⌘. / ⇧⌘,）、段落对齐（⌥⌘L / T / R / J）、列表（⇧⌘8 项目符号、⇧⌘7 编号）、⌘= / ⌘- 缩放（拦住浏览器自己的缩放）、⇧2 缩放到选区、⌘↵ / ⇧⌘↵ 从当前页 / 第一页演示。标点也按物理键认（写美式键盘不按 Shift 时的字，所以放大写成 `shift+=`，字号加大写成 `mod+shift+.`）。演示、复制为 PNG 这几个命令由界面层注册，快捷键表只引用 id。单元测试检查每条绑定都指向注册了的命令、没有重复的按键。
- 回车、Tab 只在焦点在画布上（或者没有焦点）时当快捷键：焦点在面板的按钮上时，回车是按下按钮、Tab 是移动焦点。编辑文字时按键交给隐藏的输入框，快捷键表里改字号、对齐、列表的那几条照样能用。
- **新命令**（`editor/src/commands/select.ts` 等）：选择父级、子级、下一个 / 上一个同级、反选、全选同样填充 / 描边 / 字体 / 类型 / 同一组件的实例（范围是当前这一页或整个画布，看不见、锁定的不算）、锁定 / 隐藏来回切换（选中的里面有没锁的就全锁上，否则全解锁）、全部解锁、全部显示、拼合、创建或释放蒙版、键盘改大小（连续按是一步撤销）、复制一份并挪动、缩放到选区、字号按档位加减（6、7、8……72、80、96……288，超出按 1.25 倍）。
- **选择工具**：⌘ 单击直接选中鼠标下最里面的对象，不管套了几层编组（`editor.pickDeep`）。鼠标停在对象上时用细线描出单击会选中的那个（形状描轮廓，别的描外框；按着 ⌘ 时描深选会选中的那个），鼠标离开画布时去掉；这只是覆盖层的状态，不进编辑器状态，界面不会跟着重渲染。框选按着 Shift 加选、Alt 减选、⌘ 选编组里的成员（一层层展开到不是编组为止），框选中按住空格挪动整个选框。移动时按住 Shift 锁定在 0°、45°、90°……的方向上（原来只有水平和垂直），长度取在这个方向上的投影。
- **Alt 拖动复制**：拖动开始时按着 Alt，或者拖到一半按下：原件回到原处，在它上面复制一份（`cloneNodes`，和 ⌘D 同一份代码：新 id、新血缘；画板整个复制，保留子节点的血缘，动画跟着换），拖的换成副本，指针变成复制的样子；拖到一半松开 Alt：副本删掉，拖的换回原件。来回切换都在同一个合并键里，整个过程是一步撤销；按 Esc 副本消失、选区回到原件。松手时副本照常按位置换归属（拖到别的幻灯片上就进那一页）。实例里的东西不能复制，这时 Alt 不起作用。
- **缩放**：按住 Alt 中心不动，拖动的边和对边一起变；Shift+Alt 是从中心等比。**旋转**：除了选区框上方的手柄，鼠标在选区框四个角外侧 8 到 20 像素时也能拖着旋转（手柄被别的东西挡住时也转得了）。**画矩形、椭圆**：按住 Alt 以起点为中心往外画，拖动中按住空格挪动正在画的形状。
- 验证：单元测试检查按物理键匹配（伪造 `key: '˚', code: 'KeyK'` 的事件配上 `mod+alt+k`，标点同样）、显示的写法、`abandon` 的几种情况、移动 / 框选 / 画矩形拖到一半取消，以及上面每个新命令、Alt 拖动复制（中途松开、再按下、Esc、一步撤销）、Shift 45°、⌘ 深选、⌘ 框选成员、Alt 框选减选、Alt 从中心画和缩放、空格挪动正在画的矩形、字号档位。在 Chrome 里用派发的指针和键盘事件实测：画矩形拖到一半按 Esc，矩形消失；拖动中按下 Shift、鼠标不动，矩形立刻变成正方形，松开 Shift 又变回去；⌥A（`key` 是 `å`）把两个矩形左对齐；Alt 拖动后原件留在原处、副本到了松手处，拖动中指针是复制的样子；悬停时对象描出了轮廓。Windows 上 Alt 加字母可能被浏览器占用（Chrome 的 Alt+D 是地址栏），还没有在 Windows 上测过。

### 菜单

右键菜单、顶部菜单栏、命令面板、快捷键表用同一份菜单项定义（`apps/web/src/menus/`），不会出现"右键里有、菜单里没有"。原来画布上的右键被直接拦掉，整个软件没有右键菜单，顶栏只有一个"文件"菜单。

- **菜单项**（`model.ts`）：一项是一个命令（`command` + `args`，能不能点看命令的 `enabled`，快捷键从快捷键表里取）、一个界面上的操作（`run`，比如打开对话框）或者一个子菜单。菜单用 `registerMenu(id, build)` 注册，`build` 拿到上下文（编辑器、右键点到了什么、面板里点到的那一项）返回菜单项；扩展功能用 `extendMenu` 往已有的菜单里加。多余的分隔线自动去掉；和这类选区无关的整组不出现（选中的不是图片就没有"图片"子菜单），相关但现在做不了的变灰。
- **名字**（`labels.ts`）：命令（连同参数）叫什么，是一张表，菜单、命令面板、快捷键表都查它，同一个命令到处叫同一个名字。带参数的查不到时退回不带参数的那一条（四个方向的微移都叫"微移"）。这个文件不依赖浏览器，单元测试检查每条快捷键都有名字、名字在两个语言包里都有。
- **右键点到了什么**由编辑器决定（`editor.contextAt`）：正在编辑文字时是文字菜单，选区不动；点在画板名上选中画板；点在没选中的对象上先选中它；点在已经选中的对象上、或者选区框里的空白处，保持选区；点在画板空白处、画布空白处取消选区（这样"粘贴到这里"有位置可放）。同时返回鼠标下所有重叠的对象（`editor.nodesAt`，从上到下），"选择图层"子菜单列出它们，悬停一项时画布上高亮它。输入控制器把 `contextmenu` 事件交给界面层设的 `editor.contextMenuHandler`；Mac 上 Ctrl+单击会先来一个左键按下，这一下不交给工具。键盘的菜单键、Shift+F10 打开选区的菜单，位置在选区中间。
- **各处的右键菜单**（`definitions.ts`）：画布上的对象（剪贴板各项、创建副本、删除、重命名、选择图层、按条件选择、层序、对齐分布、翻转旋转、编组、蒙版、布尔、路径、组件、图片、移到幻灯片、锁定、隐藏、导出）；正在编辑的文字（剪切、复制、粘贴、全选、粗斜体下划线删除线、字号、完成编辑；剪切复制用 `execCommand`，粘贴用异步接口读文字再插进输入框）；画板（粘贴、选择画板、重命名、复制、删除、设为或取消幻灯片、适应内容大小、全选、全部显示和解锁、导出）；画布空白处（粘贴、全选、新建画板、缩放、全部显示和解锁）；幻灯片缩略图（在后面新建一页、复制、删除、剪切复制粘贴整页、切换效果、调整顺序、从这一页播放、导出）；图层的一行（在画布上显示、只显示这个，加上对象菜单）；资源面板的组件、颜色样式、文字样式（套用、选中用了它的对象、删除等）。
- **菜单的样子**（`MenuList.tsx`）：贴着鼠标弹出，超出窗口时翻到另一边、比窗口还高时里面滚动；子菜单悬停 150 毫秒才打开、才换，鼠标进了子菜单就取消路过别的项时排上的切换，斜着往子菜单移动时不会把它关掉；键盘 ↑↓ 移动、→ 打开子菜单、← 关掉、回车执行、Esc 关一层、打字母跳到以它开头的项；点外面、滚动、窗口失去焦点时关掉，关掉后焦点还给原来的地方（通常是画布），执行的命令把焦点挪到了别处（改名框）时不管。
- **顶部菜单栏**：文件、编辑、对象、文字、视图、帮助。打开一栏后鼠标移到别的栏直接切过去，← → 在栏之间移动；窗口窄于 1180 像素时收进一个按钮，每一栏变成子菜单。文件菜单原来的对话框（新建、存为模板、导出 SVG、导出视频）改成由 `openFileDialog` 打开，菜单项在菜单栏里；文件菜单里加了"插入图片"。
- **命令面板**（⌘K）：把菜单栏的每一栏摊平，子菜单的路径写在名字前面（"对象 › 层序 › 置于顶层"），按当前语言和英文的名字一起搜，能执行的排前面；还能跳到某个图层、某一页。
- **快捷键表**（?）：按分组列出当前生效的所有快捷键（`keymap.list()`），同一组里名字相同的合成一行（四个方向的微移），可以搜索。
- **重命名**（⌘R、菜单）：命令发出一个请求，左栏切到图层页，那一行进入改名状态。
- **新命令**（`editor/src/commands/organize.ts`）：移到幻灯片（保持在画板里的相对位置，原来那一页的动画去掉）、调整幻灯片顺序（上移、下移、移到开头、移到末尾）、设为或取消幻灯片、画板适应内容（大小正好框住对象，对象在画布上不动）、只显示这个（再点一次全部显示回来）、按样式选择、图片恢复原始比例。
- 验证：单元测试检查右键点到什么时选区怎么变、鼠标下的对象从上到下、上面每个新命令、名字表的覆盖和两个语言包、多余分隔线的整理。在 Chrome 里用 1400 × 860 的视口实测：右键对象弹出对象菜单，快捷键显示成 ⌘X、⇧⌘V 这样，做不了的项变灰，悬停"对齐与分布"打开子菜单；菜单栏打开"编辑"；幻灯片缩略图、图层的一行右键弹出各自的菜单，从图层菜单点"重命名"那一行进入改名状态；⌘K 打开命令面板，搜 "align left" 得到对象的左对齐和文字的左对齐；? 打开快捷键表，八个分组、七十行。只在 Chromium 内核里试过；菜单的键盘操作只测了单元测试以外的派发事件，读屏软件没有试。

### 面板系统

原来左栏是写死的（幻灯片条只在幻灯片视图出现，下面是"图层 / 资源"两页），右栏是属性面板，位置都不能动。现在所有面板都放在停靠区和浮动窗里（`apps/web/src/dock/`）。

- **模型**（`layout.ts`，纯函数，在 Node 里测）：左栏、右栏、画布下方三个停靠区，每个停靠区从上到下（下方是从左到右）放几个面板组，每组是一排选项卡，按比例分高度；另外有浮在画布上的浮动窗（后面的在上层）。改布局的都是纯函数：挪选项卡（并进某一组的某个位置、在停靠区里拆出新组、变成浮动窗）、关闭、切换、打开（已经在了就切过去，不在就放到默认的地方）、来回开关、改停靠区大小（有上下限）、改组的比例、改浮动窗、放到最上层、隐藏全部。读回来的布局用 `normalize` 整理：结构不对就用默认的，不认识的面板去掉，同一个面板只留第一次出现的，浮动窗挪回窗口里。
- **默认布局**：左栏一组 [幻灯片 | 图层 | 资源]，右栏 [属性]，下方 [备注] 收起着。切到幻灯片视图时，幻灯片面板在某一组里但没在看的话自动切过去。布局记在浏览器里（`shiba.dock`），浏览器窗口变小时浮动窗挪回来。
- **面板注册**（`registry.ts`）：`registerDockPanel({ id, titleKey, component, defaultPlace, floatSize })`，窗口菜单里自动列出来。属性栏的分区按 id 临时生成（`inspector:分区 id`）。内置的有幻灯片、图层、资源、属性、备注、图片调整（`panels.tsx`）。
- **拖选项卡**（`drag.ts`）：按下挪出 8 像素才算开始拖，之前是普通的点击。指针下面是选项卡栏时并进那一组（按指针在哪两个选项卡之间算位置，画一条竖线）；在停靠区里一组的上（左）四分之一是拆到它前面、下（右）四分之一是拆到它后面（画一条横线），中间是并进这一组（整块高亮）；收起或者空着的停靠区是那条细边；别的地方（画布上）变成浮动窗（画出浮动窗的范围）。跟着指针显示面板的名字，Esc 取消。用指针事件实现，不用 HTML5 拖放：拖影没法控制，自动化测试也触发不了。
- **停靠区**（`DockHost.tsx`）：内侧的边拖动改宽度（下方改高度），双击恢复默认；两组之间的分隔条拖动改比例；第一组右上角的按钮把整个停靠区收起成一条竖着写着面板名字的细边，点名字展开。空的停靠区不占地方，拖选项卡时边上出现一条可以放的细边。⌘\ 隐藏全部面板，只留画布和顶栏。
- **浮动窗**：拖标题栏的空白处移动，贴近窗口边缘、别的浮动窗的边 8 像素以内时贴上去；拖右下角改大小（有最小尺寸）；双击标题栏或者点按钮折叠成只剩标题栏；关闭按钮关掉里面的面板；点一下放到最上层。浮动窗放在画布上方的一层，这一层本身不接收鼠标事件。
- **选项卡的右键菜单**：关闭、变成浮动面板、停靠到左栏 / 右栏 / 下方、恢复默认布局。**窗口菜单**：所有面板（打勾表示正在显示，点了打开或关掉）、工作区 ▸（设计、演示、修图三套预设）、恢复默认布局、隐藏界面。⌥1 / ⌥2 / ⌥3 打开并切到图层、资源、幻灯片。重命名（⌘R）时先打开图层面板。
- **属性栏的分区可以弹出**：每一节的标题右边有"弹出"按钮（悬停时出现），弹出后成为浮动面板（跟着选区走，对选区没意义时显示提示），属性栏里这一节换成一行"在浮动面板里"，点它把面板找回来。图片那一节弹出的是专门的图片调整面板。
- **图片调整面板**：浮动，比属性栏宽；跟着选区走，选中的不是图片时显示提示，不自动关掉（Photoshop 的属性面板也是这样）。图钉按下后固定在这张图片上，选别的东西也不变——图片面板原来用 `updateSelection` 改选中的对象，改成改面板显示的那几个对象，在属性栏里结果一样。按住"看原图"时画布上这张图片暂时不带调色、曲线、滤镜：用一个合并键临时改掉，松开时用 `abandon` 整个放弃，不进撤销历史。
- **备注面板**：下方停靠区，当前这一页的演讲者备注，选中对象时也能写（属性栏里没选中对象时那一节还在）。

### 吸附、参考线、标尺

原来完全没有吸附，只能事后用对齐面板补救。

- **吸附引擎**（`editor/src/snap.ts`，纯函数）：候选是当前视图里的对象（正在动的对象所在编组里的其他成员也算）、画板、辅助线，每个对象和画板贡献左中右三条竖线、上中下三条横线。拖动开始时收集一次、排好序，拖动中每一帧二分查找（一万个对象时每次查找远小于 1 毫秒，单元测试里量过）。x、y 分开找：移动对象的三条线里离候选最近、在阈值以内的那条对上。吸附距离是屏幕上 5 像素按缩放换算。
  - **等间距**：和移动对象在另一个方向上有重叠的对象里找左右（上下）邻居，候选位置是两个邻居正中间，或者接着邻居和它下一个邻居之间已有的间距排；对上时画出两段间距和数字。
  - **像素**：开着"吸附到像素"时，没对上别的东西的方向把位置取整。
  - 用在：移动（含 Alt 复制、拖画板）、缩放控制柄（只吸正在动的那条边；单个对象转过角度时不吸）、画矩形和椭圆（起点和终点）、钢笔放下的锚点、拖辅助线。方向键微移不吸。按着 ⌘ 暂停吸附；Shift 锁定在斜线方向上时不吸（吸了就离开那条斜线了）。
- **智能参考线**：对上时从移动的对象画一条洋红色的线到所有对齐在这条线上的东西，两头画小叉；松手、取消时去掉（`editor.snapFeedback`，只在覆盖层，不进状态）。
- **按住 Alt 测距**：选中对象后按住 Alt，鼠标停在另一个对象上时画出两者之间上下左右的距离；停在空白处时画到所在画板四边的距离；选中的在目标里面时画到它四条边的内边距。不用拖动，松开 Alt 就消失。输入控制器在没拖动时按下、松开修饰键也会告诉工具，所以不用动鼠标。
- **尺寸标签**：选中对象时选区框下面常驻"宽 × 高"（一个对象时是它自己的大小，转过角度也是；几个对象时是整体外框），测距时不画免得叠在一起。旋转时鼠标旁边显示第一个对象转了多少度。
- **标尺**（⇧R）：画在画布的上边和左边，盖在画布上（Figma 也是这样）。原点在当前画板的左上角（幻灯片视图里是当前这一页，画布视图里是选中对象所在的画板，没有就是页面原点）。主刻度的间隔让相邻两个数字隔开至少 60 屏幕像素（1、2、5、10、20、25、50……），选中对象的范围用浅色标出来。
- **辅助线**：数据是画板或页面的 `guides`（`{ id, axis, offset }`），可选字段，`validate.ts` 校验（方向只能是 x、y，位置是有限数，一个画板最多一千条）。从标尺上拖出来：松手在画板里属于这个画板，坐标相对画板，只画在画板里、跟着画板移动，复制这一页时一起复制；松手在画板外属于页面，画满画布。拖的时候按 Alt 换方向，按 Shift 吸附到标尺的小刻度，平时吸附到对象。选择工具下鼠标靠近辅助线 3 像素时指针变成双箭头，拖动改位置，拖回标尺上删除（一步撤销）；单击选中（画成洋红色），按 ⌫ 删除；双击输入精确的位置。选区的控制柄比辅助线优先。⌘; 显示或隐藏，⌥⌘; 锁定（点不中、拖不动）。导出、播放器都不画辅助线。逻辑在 `editor/src/guides.ts`，输入控制器在交给工具之前先问它。
- **像素网格**（⌘'）：放大到 800% 以上时画出像素格。
- **视图选项**：标尺、辅助线、锁定辅助线、像素网格、尺寸标签、三种吸附放在编辑器状态的 `view` 里（`view.toggle` 命令切换），界面层记在浏览器里，下次打开还是这样；视图菜单、画布空白处的右键菜单里都能开关。右键点到辅助线弹出辅助线菜单（设置位置、删除、锁定、清除全部），点到标尺弹出标尺菜单，画板菜单里有"清除这个画板的辅助线"。
- 验证：单元测试检查吸附引擎（边对边、中线、只吸允许的方向、取整、画板和辅助线、两种等间距、点吸附、一万个对象的查找速度）、测距（不相交、在里面）、拖动对象时吸过去且有参考线、⌘ 不吸、关掉开关不吸、像素取整、画矩形时起点吸附、辅助线的拖出 / 改位置 / 拖回标尺删除 / 撤销、页面上的辅助线、Alt 换方向和 Shift 吸附刻度、移动对象吸到辅助线、锁定后点不中、选中删除、命令、右键点到辅助线、复制这一页带上辅助线、文件校验。在 Chrome 里用派发的事件实测：⇧R 打开标尺，从上边的标尺拖出一条横线到画板里，刷新页面后标尺还开着、辅助线还在；拖一个矩形让它的左边靠近另一个矩形的左边，对齐过去并画出洋红色的参考线；按住 Alt 悬停在另一个矩形上画出距离；选区框下面显示"150 × 100"。

### 剪贴板

对象的复制、剪切、粘贴。数据和放置规则在 `editor/src/clipboard.ts`（纯逻辑，在 Node 里测），浏览器剪贴板接口在 `apps/web/src/clipboard.ts`。原来只有 ⌘D 创建副本，粘贴只认图片。

- **写进剪贴板的东西**：选中的最外层对象和它们的子孙（按层序从下到上），每个最外层对象的变换换算到它们最近的公共父节点（来源容器）的坐标里；来源容器的 id、范围、本地到世界的变换；内容在容器里的外框；用到的资源（图片、PDF 文字的字形库），合计不超过 20MB 的内容写成 base64，超过的只记 id；来源文档根页面的 id。整个 JSON 转成 base64 放进 `text/html` 里一个元素的属性（Figma 也是这么做的：`text/html` 在所有浏览器、跨标签页都能用，浏览器读剪贴板时的过滤会保留属性）。同时写 `text/plain`：文本写文字，别的写名字，粘到聊天软件里不是一堆数据。
- **快捷键走浏览器事件**：⌘C / ⌘X / ⌘V 用 `copy`、`cut`、`paste` 事件，同步、不弹权限提示，所以这三个键不放进快捷键表（快捷键表命中时会拦住按键，事件就不来了）。焦点在输入框里、正在编辑文字时交给浏览器。⇧⌘V 原位粘贴：按下时记一下，紧接着来的 `paste` 事件按原位处理；120 毫秒内没等到事件就自己用异步接口读。菜单里的复制、粘贴（`edit.copy`、`edit.paste`、`edit.pasteInPlace`、`edit.pasteHere` 等命令，注册在界面层，因为要用浏览器接口）用异步剪贴板接口，Chrome 第一次会问权限；读不到时退回这个页面里最近一次复制的内容，还没有就提示用 ⌘V。
- **粘贴进哪个容器**：选中的是画板就粘进它里面；选中了别的东西就粘进它们所在的容器，层序紧挨在它们上面；都没有时是当前这一页（幻灯片视图）或者视口中间的画板。实例里不能加东西，碰到实例往外退。里面有画板时放在页面上。
- **放在哪里**：
  - 目标容器和来源容器一样大，或者内容在原来的相对位置放得下，就保持相对位置（第 3 页的标题粘到第 5 页还在同一个地方）；放不下就居中。粘到页面上时世界坐标不变，看不见的话挪到视口中间。
  - 粘到原来的位置、原件还在那里时，往右下错开 16（和 ⌘D 一样）；接着再粘同一份内容，每次多错开 16。每复制一次剪贴板数据有一个新 id，靠它认"同一份"。
  - 原位粘贴：世界坐标不变。粘贴到这里：内容的中心放在右键的位置。
  - 粘贴的画板放在已有画板的右边，是幻灯片的话排在当前页后面，动画换成指向新节点的那一份。
- **换 id**：所有节点换新 id、新血缘，序号按类型接着数。同一份文档里复制主组件再粘贴，得到它的一个实例（和 Figma 一样，免得多出一个主组件）；单独复制实例里嵌套的实例，重新做一个那个组件的实例。实例的主组件这份文档里没有（别的文档、或者已经删了）时分离成普通编组；主组件和它的实例一起复制到别的文档时，实例跟着新的主组件。实例里的副本单独粘出来是普通对象。主组件不能粘进主组件或实例里，这时去掉主组件标记；粘进去会让主组件里出现自己的实例时放到页面上。链接的颜色、文字样式这份文档里没有时断开链接，值留着，不往别人的文档里塞样式。动画不跟着对象走（动画属于幻灯片）。
- **资源**：带了内容的按内容重新算 id，不信任剪贴板里写的 id（图片先过一遍渲染器能不能解码）；没带内容、这份文档里也没有的计数，粘贴后提示有几张图片没带过来。
- **不可信输入**：剪贴板里的数据和打开的文件一样检查：节点照 `validate.ts` 校验（容器当成根页面，成环、类型不对、主组件套主组件都拒绝），画板只能在最外层，节点数不超过两万，资源只收认识的类型，id 必须是 40 位十六进制。
- **从外面粘贴**：图片放到画布上（原来就有，从文件菜单挪了过来）；.shiba 和 PDF 文件直接打开；纯文字在视口中间建一个文本，最长的一行超过 80 个字时改成 480 宽、自动折行。
- **复制为 PNG / SVG**（⇧⌘C 和菜单）：一个对象用渲染器导出两倍图；几个对象先导出成 SVG（文字转轮廓）再画到画布上编码成 PNG。写进剪贴板时 `ClipboardItem` 收一个 Promise，Safari 要求写剪贴板的调用发生在这次点击里，内容可以晚一点到。复制为 SVG 写的是 SVG 源码。⇧⌘C 在 Chrome 里可能被开发者工具占用，菜单里照样能用。
- **复制属性、粘贴属性**（⌥⌘C / ⌥⌘V，`editor/src/commands/properties.ts`）：记下一个对象的不透明度、混合模式、填充、描边、圆角、文字样式和对齐，套到选中的对象上；文本只收纯色，画板不收图片。只记在编辑器里，不写进系统剪贴板，免得冲掉用户刚复制的东西。
- **⌘D 重复上次的偏移**：创建副本后紧接着把副本挪了一段再按 ⌘D，按同样的偏移继续复制；选区换了就恢复默认的错开 16。
- 验证：单元测试覆盖放置规则的每一条（错开、连续粘贴、剪切后放回原处、一样大的页面保持相对位置、小画板居中、原位、粘贴到这里、层序）、组件（主组件粘出实例、跨文档分离和跟着新主组件、实例里的副本）、样式断开、图片带过去和缺失计数、画板粘贴的顺序位置和动画、HTML 往返和坏数据拒绝、复制属性、纯文字、⌘D 的偏移。在 Chrome 里用派发的 `copy`、`paste` 事件实测：第一页的矩形复制后粘到第二页，位置完全一样；粘贴外部的纯文字得到文本。真实的系统剪贴板（异步接口的权限提示、跨浏览器）还没有实测，Safari、Firefox 没测。

### 直接选择工具

原来钢笔画完就不能改锚点。

- **工具**（`editor/src/tools/direct-select.ts`，快捷键 A；选中路径后按回车、双击路径也能进来）：单击锚点选中，Shift 加选，在空白处框选锚点；拖锚点挪动选中的几个（Shift 锁定水平或垂直，吸附到对象，按着 ⌘ 不吸）；拖选中锚点的控制柄改曲线，平滑锚点（两根控制柄共线、方向相反）的另一根反向跟着转、长度不变，按住 Alt 只动这一根；双击锚点在尖角和平滑之间切换（平滑的控制柄沿前后两个锚点的连线方向，长度是到前后锚点距离的三分之一）；⌫ 删除选中的锚点（路径保持连着，剩不到两个锚点的子路径去掉，全删光了删掉对象）；方向键微移锚点；Esc 先取消选中的锚点，再回到选择工具；回车、双击空白处回到选择工具；点别的形状换成改它。拖动中按 Esc 撤回。
- **矩形、椭圆**：直接选择工具里显示按轮廓换算出来的锚点，开始拖的时候先拼合成路径（`path.flatten`，id 和血缘不变），再挪。
- **钢笔在选中的路径上**：还没开始画的时候，停在选中路径的锚点上指针变成"禁止"，单击删掉这个锚点；停在线段上指针变成"加号"，单击在这里加一个锚点（de Casteljau 把曲线拆成两段，形状不变）。
- 改完锚点后把节点的外框重新对齐到路径的实际范围（`normalizePath`：锚点平移到以外框左上角为原点，变换矩阵相应地挪，路径在画布上不动），和挪锚点是同一步撤销。改锚点的纯函数在 `editor/src/path-edit.ts`（找最近的线段、拆线段、删锚点、切换尖角平滑、挪锚点、挪控制柄）。
- 验证：单元测试检查拆线段形状不变、找线段、删锚点、尖角平滑来回切换、控制柄的对称和 Alt 断开，以及在编辑器里拖矩形的锚点（先转成路径、id 不变、外框重新对齐、在画布上的范围对）、框选两个锚点按 ⌫ 删掉、双击锚点变平滑、钢笔在线段上加锚点和在锚点上删锚点。在 Chrome 里实测：选中矩形按 A，拖右下角的锚点，矩形变成路径、那个角跟着走。

### 顶点圆角

原来只有矩形有一个统一的 `cornerRadius`，在属性面板里输入。

- **数据**：矩形加了可选的 `cornerRadii`（左上、右上、右下、左下）、`cornerStyle`（圆角、反向圆角、倒角）、`cornerSmoothing`（0 到 1）；路径的锚点加了可选的 `radius`，路径也有 `cornerStyle`、`cornerSmoothing`。都省略时和以前一样，旧文件不用迁移；`validate.ts` 校验（四个非负数、认识的样式、0 到 1）。组件的覆盖按属性名记，自动支持。
- **几何放在 core**（`core/src/corners.ts`）：把"带圆角的折线"换成普通的贝塞尔锚点。每个角按半径算出切点到顶点的距离（圆角是 r / tan(θ/2)），一条边两头的角加起来超过边长时按比例缩小，所以半径太大时自动收小。圆角用三次曲线近似圆弧（控制柄 (4/3)·tan(φ/4)·r，离真正的圆弧不到半径的万分之三）；倒角是直线；反向圆角是以顶点为圆心往里凹的圆弧；平滑度把切点往两边推、控制柄往顶点拉，近似 iOS 图标那样连续的圆角。路径只圆"两边都是直线的尖角"，有曲线的子路径里别的锚点原样保留。
- **渲染和导出**：渲染器的矩形四个角一样、普通圆角时仍用 Skia 自己的圆角矩形（`rectNeedsCorners` 判断），其余按 corners.ts 生成；路径的锚点带半径时先换成普通锚点。命中、导出 PDF（写轮廓）、轮廓化描边、偏移路径、布尔运算、拼合都走同一个轮廓，所以处处一致。导出 SVG 时只有四个角一样的普通圆角矩形写成 `<rect rx>`，其余写成路径。缩放时半径不变（"缩放只改几何"），路径缩放时锚点的半径保留；复制属性带上圆角的几项。
- **画布上的圆角控件**（`editor/src/corner-handles.ts`）：只选中一个矩形或者带尖角的路径、而且它在屏幕上的短边不小于 40 像素时，每个能圆的角里面有一个小圆点，放在圆角的圆心（半径是 0 时离角 14 屏幕像素）。拖它所有的角一起变（矩形写 `cornerRadius`、去掉 `cornerRadii`），按住 Alt 只改这一个角；半径按鼠标在角平分线上的位移换算（圆心沿平分线移动 d，半径变 d·sin(θ/2)），按相对位移算，按下时不跳，取整，不超过能放下的最大值（到了最大值控件画成洋红色）。拖动时鼠标旁显示"R 半径"，一次拖动是一步撤销。Alt 单击控件在圆角、反向圆角、倒角之间轮换。控件比移动、缩放优先点中。
- **属性面板**（位置与大小一节，`CornerFields.tsx`）：一个半径（几个对象不一样、或者四个角分开设了时显示空白），"四个角分开"展开成四个框（只对矩形），样式三选一，平滑度（百分比）。路径的半径框改所有能圆的锚点。
- 验证：单元测试检查 corners.ts（圆角的切点、曲线离圆弧的误差不到 0.006、半径太大按边长收小、相邻的角各用各的、倒角是直线、反向圆角往里凹、平滑度 0 时和普通圆角一样、矩形什么时候要按这里的算法、路径里只有两边都是直线的尖角能圆、文件校验），渲染器里按 corners.ts 生成的圆角矩形和 Skia 自己的圆角矩形栅格化比较（只在圆弧边缘的抗锯齿上差，是两种曲线拆成小线段的容差不同），编辑器里的控件（够大才出现、多选不出现、位置、拖动一起变、Alt 只改一个、一步撤销、不超过短边的一半、Alt 单击轮换样式、拼合出来的路径每个角都有控件、缩放后半径还在）。在 Chrome 里实测：画一个矩形，按住 Alt 把右下角的控件往里拖，只有右下角变圆，属性面板的半径显示空白；导出 SVG 写成路径。

### 工具

原来工具栏上只有选择、矩形、椭圆、钢笔、文本、抓手，画完一个形状就回到选择工具。

- **工具栏分组**（`apps/web/src/toolbar.ts`、`components/ToolGroup.tsx`）：选择组（选择 V、直接选择 A、缩放 K）、形状组（矩形 R、椭圆 O、直线 L、箭头 ⇧L、多边形、星形）、钢笔组（钢笔 P、铅笔 ⇧P）、文本 T、吸管 I、视图组（抓手 H、视图缩放 Z）。有几个工具的组显示上次用的那个（记在 localStorage），右下角一个小三角；点小三角、右键、或者按住半秒展开，列出组里的工具和快捷键。用快捷键切到组里的某个工具时，组的按钮也换成它。
- **锁定**：双击工具按钮锁住它，画完不回到选择工具，可以连续画（按钮右上角一个小点）；单击锁着的按钮、按 Esc、或者换别的工具时解开。编辑器里是 `editor.lockTool(id)` 和 `editor.toolLocked`，各个画图工具画完时看它决定回不回选择工具。
- **直线和箭头**（`editor/src/tools/line.ts`）：拖出一条两个锚点的开放钢笔路径，只有描边（2 像素），之后可以用直接选择工具改。按住 Shift 方向锁定在 45° 的倍数上，按住 Alt 以起点为中点往两边画，起点终点吸附到附近的边和中线（按着 ⌘ 不吸）。箭头工具画的线终点带一个开口的箭头。
- **箭头样式**：描边加了可选的 `arrowStart`、`arrowEnd`（箭头、实心三角、圆点、方块、横杠），只对开放的子路径起作用，省略时没有箭头；`validate.ts` 校验。箭头的大小随线宽变（`core/src/stroke.ts` 的 `arrowMetrics`）。几何放在 core（`core/src/arrows.ts`）：每个开放子路径的两头算出箭头的尖和朝向（端点的控制柄方向，没有控制柄时取前一个点），实心的箭头下面把线沿曲线缩回去一点（de Casteljau 在按弧长找到的位置拆开曲线），免得平头的线从箭头尖两边露出来。渲染器的 `arrowPaths`（`renderer/src/arrows.ts`）把它变成两条 Skia 路径：缩短的线拿去描边，箭头按描边的颜色填充（开口的箭头和横杠是按线宽描出来的轮廓）。画布、导出 PDF、导出 SVG 都用这两条路径，画出来一样；画出来的范围（`drawnBounds`）包括伸出外框的箭头。属性面板的外观一节在选中开放路径时多一行"箭头"，起点终点各一个下拉框。
- **多边形和星形**：新的节点类型 `polygon`（`sides` 边数 3 到 60、可选的 `innerRatio` 内径比例、`cornerRadius` 和圆角样式），有 `innerRatio` 时是星形，图层面板里按"多边形""星形"分开命名。顶点和轮廓在 core（`core/src/polygon.ts`）：在外框里画内切的正多边形，第一个顶点朝上；星形的外顶点和内顶点交替。圆角用顶点圆角的同一套几何（`roundPolygon`），所以渲染、命中、导出、布尔运算、轮廓化描边都一致。多边形工具默认画三角形，星形工具默认画五角星（内径 38.2%）。属性面板有一个"多边形"分区：多边形和星形互相切换、边数（角数）、内径；圆角在位置与大小一节里改。
- **铅笔**（`editor/src/tools/pencil.ts`、`editor/src/curve-fit.ts`）：按住拖动手画，松手后把画过的点拟合成几段三次贝塞尔曲线（Schneider 的算法：先用一段曲线最小二乘拟合，误差超过容差就在误差最大的点拆开，拆开处切线连续；拟合前去掉挨得太近的点、用 Douglas–Peucker 粗简化）。容差是屏幕上 2.5 像素换算成文档单位。松手时回到起点 10 像素以内算闭合的形状（首尾接口两边的切线取同一个方向），有填充；结果是普通的钢笔路径。
- **吸管**（`editor/src/tools/eyedropper.ts`）：点一个对象，把它的外观（填充、描边、不透明度、混合模式、圆角、文字样式）套到选中的对象上，按住 Alt 只取填充；和"粘贴属性"用同一份代码（`applyPropertiesFrom`）。
- **视图缩放**（`editor/src/tools/zoom.ts`）：单击放大一倍，按住 Alt 单击缩小一半（点的位置不动），拖出一个框缩放到正好放下这个框。
- **等比缩放**（缩放工具 K，`editor/src/tools/scale.ts`、`editor/src/scale.ts`；菜单"排列 → 等比缩放"按百分比）：普通的缩放只改几何，描边、圆角、字号不变；等比缩放连描边粗细、虚线、圆角（矩形四个角、多边形、路径锚点的半径）、字号、字距、段距、缩进一起按同一个比例变，整体放大一倍就是看起来放大了一倍，做 UI 时常用。几何照常用 `resizeInWorld` 改（不往变换矩阵里塞缩放），参数都从拖动开始时的原样乘比例，拖动中不会越乘越大。缩放中心默认是选区中心，按住 Alt 单击可以换一个（换了选择就回到选区中心），画布上用一个小十字标出来；拖动时鼠标旁显示百分比，Esc 撤回。
- 验证：单元测试检查箭头的几何（尖和朝向、实心的缩线开口的不缩、起点朝反方向、曲线端点按控制柄、缩短后的线还在曲线上、闭合的没有箭头）、多边形的顶点（在内切椭圆上、第一个朝上、星形内外交替、边数限制、有圆角时每个顶点变两个锚点）、文件校验，渲染器里画出的箭头（离线 4 像素的地方被三角箭头盖住、没有箭头时不盖、画出的范围包括箭头），导出 PDF 读回来是一条缩短的描边线加一个按描边颜色填充的三角形、星形是十个锚点的闭合路径，导出 SVG 是一条描边的线加一个填充的箭头路径，编辑器里直线（尺寸和锚点、Shift 45°、Alt 从中点、点一下不画、Esc 撤回）、箭头（终点有箭头、一步撤销）、多边形和星形、锁定（连续画、换工具解开、Esc 解开且选中的不变）、曲线拟合（正弦曲线离画过的点不超过容差、直线只剩两个锚点、闭合时接口平滑）、铅笔画圈是闭合的形状（离原来的圆不到 3 像素）、缩放工具（两倍时尺寸描边虚线圆角一起变、Alt 单击换中心、Esc 撤回）、等比缩放命令、吸管（Alt 只取填充）、视图缩放。在 Chrome 里实测：从形状组的菜单里选多边形、双击锁住，画三角形和星形、改圆角；箭头工具画线，在属性面板里把起点换成圆点、终点换成三角；铅笔画一圈得到闭合的形状；选中星形按 K 往里拖，描边和圆角跟着变细变小。

### 画框

画板是顶层的（同时是幻灯片的一页），不能嵌套；编组没有自己的外观、不裁剪。做界面时一屏里面套着卡片、卡片里套着按钮，每层都要有背景、圆角、裁剪，所以加了一种新节点 `frame`，而不是让画板能嵌套（那样幻灯片的很多规则要改）。

- **数据**（`core/src/model.ts` 的 `FrameNode`）：大小、填充、描边、圆角（和矩形一样的四个字段，`hasBoxCorners` 把矩形和画框当成一类）、`clip`（裁不裁剪超出范围的内容）。可以放在画板里、页面上，也可以互相嵌套。`validate.ts` 校验圆角和裁剪开关。
- **渲染**：节点类型的注册表加了两个钩子：`clips(node)`（`children` 是 `clip` 的容器要不要裁剪，不提供时总是裁，画板就是这样）和 `strokeOver`（描边画在子节点上面）。画框先画填充，再画子节点（裁剪时按自己的轮廓裁，圆角也算），最后画描边，描边不会被里面的东西盖住。画布、导出 PDF（裁剪写成裁剪路径）、导出 SVG（写成 `<clipPath>`）都按这个顺序；播放器和视频的图层走 SVG 导出，自然认得画框。关了裁剪的画框画出来的范围包括伸出去的东西，视口剔除时不按自己的范围剔。
- **命中和选择**（`renderer/src/geometry.ts`、`editor.pick`）：点在画框的轮廓里，没点中里面的东西就是点中了画框（空白处也点得中，没有填充也一样）；裁剪的画框外面点不中伸出去的部分。画框和编组一样是"能进去"的容器（`core` 的 `isEnterable`）：单击里面的东西先选中画框，双击进去选里面的，之后单击里面别的也是选里面的；⇧↵ 选择父级回到画框，⌘ 框选展开到画框里面。
- **放进画框**（`editor.containerAt`）：新画的形状、粘贴的东西放进鼠标下面最里层的画框（看不见、锁定的、组件实例里的画框不算）；拖动结束时对象的中心落进哪个画框就放进去，拖出来就拿出来（`reparentByPosition`，幻灯片视图里也生效，只在这一页和它里面的画框之间换），画布上的位置不变；拖的就是画框时它不会放进自己里面，违反组件规则的不挪。
- **画框工具 F**（形状工具的一种）：在画板里（或者画框里）拖出来是白底、裁剪内容的画框；在所有画板外面（画布视图）拖出来是新画板，排在幻灯片的最后一页（和"新建幻灯片"共用 `newArtboard`）。工具栏上在选择组后面。
- **用画框包起来**（⌥⌘G，`frame.wrap`，结构菜单、右键菜单、层序面板里有按钮）：画框正好框住选中的对象（几何范围），放在最上面那个对象原来的层位；没有填充、不裁剪，所以包起来之后画布上什么都没变（描边伸出画框也不会被切掉）。取消编组（⇧⌘G）对画框也管用：去掉画框，里面的东西留下，位置不变。
- **改大小**：画框和画板一样只改自己的大小，里面的东西不动（以后按约束跟着变，见 interaction-plan.md 的 UI-2）；等比缩放（K）也只改画框自己的大小和圆角、描边。画框和矩形一样有画布上的圆角控件和属性面板的圆角（四个角分开、样式、平滑度）。属性面板有一个"画框"分区，只有"裁剪内容"一个勾选框；图层面板里画框的图标是 #，可以把东西拖进去。
- 顺带修好：属性面板的圆角原来不认多边形（`roundable` 只认矩形和路径），现在多边形、画框都有。

### 约束

原来画板、画框改大小时里面的东西一律不动。做界面时要的是按钮靠右下角、标题栏左右拉伸、图标居中。

- **数据**：节点加了可选的 `constraints: { h, v }`（`core/src/constraints.ts`）。水平方向靠左、靠右、左右都靠、居中、按比例，垂直方向靠上、靠下、上下都靠、居中、按比例；省略等于靠左靠上，也就是以前的行为（不动），旧文件不用迁移。`validate.ts` 校验两个值。一个方向上怎么算是纯函数 `constrainAxis`：靠起点不动，靠终点保持到终点的距离，两头都靠保持两边的距离（长度跟着变，至少 1），居中保持中心到容器中心的距离，按比例起点和长度一起乘。
- **改大小时**（`editor/src/resize.ts`）：`captureOriginals` 现在也记下画框和画板里面的所有后代，都从拖动开始时的原样算。画框、画板的 `scaleContent` 分支改完自己的大小后，对每个子节点取它在父坐标里的外接框（编组、布尔组是里面东西的范围），两个方向各自按约束算出新的起点和长度，再像多选缩放那样换算到子节点上：改平移，大小变了就接着缩放它的内容（转过角度的按自己的方向近似）。子节点是画框时它里面的东西接着按约束变，所以嵌套的画框、编组里的画框都对。缩放分三种（`ContentMode`）：平时按约束；拖控制柄时按住 ⌘ 里面的东西不动；等比缩放（K、"等比缩放"命令）像编组一样整体按比例缩放，描边、圆角、字号一起变。
- **属性面板**（位置与大小一节，`ConstraintFields.tsx`）：选中的对象都直接放在画框或画板里时出现。左边一个小图（方框，四条边和中间的十字可以点，亮的是当前的约束；点左边是靠左，按住 Shift 再点右边是左右都靠，点中间的竖线是水平居中），右边两个下拉框。几个对象不一样时下拉框显示空白。改成靠左靠上时字段去掉，不写进文件。
- 验证：单元测试检查 `constrainAxis` 的五种方式和长度下限、文件校验，编辑器里画框改大小时默认不动、靠右靠下、左右上下都靠、居中和按比例、⌘（不动）和等比缩放（整体按比例）、嵌套画框里靠右的东西跟着走、画板改大小时靠右下角的东西跟着走（没设约束的照旧不动）、编组按约束拉伸时组里的东西一起缩放并且一步撤销。在 Chrome 里实测：画框里放一个矩形，在属性面板里把水平约束改成靠右，往右拖画框右下角的控制柄 200，矩形跟着往右挪 200；按住 ⌘ 往回拖 100，矩形不动。

### 效果

- **数据**（`core/src/effects.ts`）：节点加了可选的 `effects`，一串投影、内阴影、图层模糊、背景模糊，按列表的顺序叠，每一项可以暂时关掉（`hidden`）。阴影有颜色（含透明度）、X、Y、模糊、扩展，模糊有半径。模糊的数值和设计软件、CSS 的写法一致：高斯模糊的标准差是它的一半。画板和页面不画效果。`validate.ts` 校验（认识的类型、有限的数字、模糊不是负数、最多 16 个）。`effectOutset` 算效果让画出来的范围往四周多出多少：投影按偏移、扩展和三倍标准差，图层模糊四周再扩三倍标准差。
- **画布**（`renderer/src/effects.ts`）：投影、内阴影、图层模糊做成一个 Skia 图像滤镜，画对象时开一个离屏层用它：层里画对象本身，滤镜在下面垫投影（`MakeDropShadowOnly`，扩展先用 `MakeDilate` / `MakeErode` 扩缩透明度），上面叠内阴影（透明度反过来、偏移、模糊、上色，再用 `SrcIn` 只留形状里面的部分），最后整体模糊。所以对文字、编组、画框一样管用，不只是形状。背景模糊在画对象之前按对象的轮廓裁剪（编组、文字按范围），开一个带背景滤镜的空层，下面已经画好的东西就被模糊了。不透明度在滤镜之后（阴影跟着一起变淡）。`drawnBounds` 包含效果，视口剔除、导出 PNG、图层图片的范围都跟着变大；编辑器给导出用的快照和 SVG 的图层范围都改成按 `drawnBounds` 算。
- **导出 SVG**：写成一个 `<filter>`（`filterUnits="userSpaceOnUse"`，范围是画出来的范围）：投影是 `feMorphology`（扩展）→ `feOffset` → `feGaussianBlur` → `feFlood` + `feComposite`，内阴影多一步 `feComponentTransfer` 把透明度反过来，最后再和 `SourceAlpha` 取交；`feMerge` 按投影、对象本身、内阴影的顺序合起来，有图层模糊时最后整体 `feGaussianBlur`。播放器和视频的图层走 SVG，自然带着效果。背景模糊 SVG 做不了（浏览器不支持取下面的画面），不写。
- **导出 PDF**：PDF 没有模糊。投影单独烤成图片垫在矢量形状下面，内阴影烤成图片盖在上面（渲染器的 `renderEffectsToPng` 只画这个节点的一部分效果，不算它自己的不透明度和混合模式，由 PDF 的图形状态另外加上），形状、文字还是矢量；有阴影又半透明时阴影和对象先合成成透明组再整体变淡，和画布一样。有图层模糊、背景模糊时整个对象连同效果画成图片（背景模糊模糊不到下面的东西，只剩对象本身）。
- **编辑**：属性面板的"效果"分区（`EffectsPanel.tsx`）：添加（默认是往下 4、模糊 8、25% 黑的投影），每一项换类型（投影和内阴影之间换参数留着）、眼睛开关、删除，阴影的颜色、透明度、X、Y、模糊、扩展，模糊的半径。选中的几个对象效果不一样时显示第一个的，改了统一成这一套。等比缩放（K）时偏移、模糊、扩展、半径按比例变；复制属性、吸管带上效果。
- 验证：单元测试检查效果的数据（标准差、关掉的不算、画板不画、外扩的范围、文件校验），渲染（投影画在偏移处、在对象下面、不影响对象本身，扩展让阴影变大，模糊让边缘变软，内阴影只在形状里面、靠偏移一边的边缘变暗，图层模糊把对象糊开，背景模糊把下面的条纹糊成灰色而外面的条纹不变，关掉的不画，画出的范围），导出 PDF 用的分部分画（只有投影、只有内阴影、都不含对象本身），导出 PDF 读回来是投影的图片、矢量的矩形、模糊的椭圆画成的图片，导出 SVG 的 `<filter>` 结构（范围、扩展、偏移、颜色、合并顺序、最后的图层模糊、关掉的不写），等比缩放和复制属性。在 Chrome 里实测：给矩形加投影和内阴影，画布上显示正确；把同一个对象分别用渲染器画成 PNG、导出成 SVG 再让浏览器画出来，逐像素比较最多差 6/255、平均差 0.48，没有一个像素差到 8 以上（两边的高斯模糊实现不同，只在阴影的柔边上有一点出入）。

- 语言包可导出为 JSON，用户翻译后导入即成为一门新语言；缺失的条目回退到英文。导入的内容按不可信数据校验。
- 内容混排：中西文字体分设、行高统一已实现；中英文间自动间距、标点挤压、行首行尾禁则待做。

### 文本

- **数据**：文本节点存内容、整段的默认样式（中西文字体、字号、字重、斜体、下划线、删除线、行高、字距；颜色是节点的填充）、默认的对齐方式和宽度模式，以及各段自己的段落样式。自动宽度只在换行符处折行；固定宽度自动折行。高度始终由排版决定。
- **字符级样式**（`core/src/text-spans.ts`）：和默认样式不同的字按区间记在 `spans` 里，每个区间只记不同的那几项。字体、字号、粗细、斜体、颜色、下划线、删除线、字距可以按字设置；行高、宽度模式是整个文本的。
  - 区间总是整理好的：按位置排好、互不重叠、相邻的相同样式合并、和默认样式相同的项去掉。大多数文本根本没有这个字段。
  - 打字时区间跟着走：新打的字接着前一个字的样式（在开头时接着后一个字）。选中一段改样式只改这一段；没选中时在光标处换样式，记下来给接下来打的字用，光标一挪就作废。
  - 选中了全部文字、或者没在编辑时改的是整段的默认样式，并从各个区间里去掉这一项：整段改成红色之后，原来单独设了颜色的字也变红。
  - 快捷键：⌘B 粗体、⌘I 斜体、⌘U 下划线、⌘⇧X 删除线。编辑时作用于选中的字，没在编辑时作用于选中的整个文本；范围里有的有有的没有时统一加上。
  - 属性面板显示选中那几个字的样式，不一致的项显示为空白；面板顶上写明这次改的是"选中的文字""接下来输入的文字"还是"整段文字"。文字颜色从外观面板移到了文本面板。
- **字体**：字体文件随应用发布，不依赖外部字体服务。每个家族按 Unicode 区间切成很多小文件，排版时只加载用到的那几个。常用汉字集中在七八个分片里，每个约 30KB。内置 Inter、思源黑体、思源宋体，以及和最常见的西文字体等宽的三款替代字体：Arimo（Arial / Helvetica）、Tinos（Times）、Cousine（Courier）。西文字体各有常规、粗体和对应的斜体；中文字体没有斜体文件，设成斜体时由排版引擎把字形斜切。
- **排版**：用 SkParagraph，每种字符样式是一段样式。每个字符由字体列表里第一个包含它的家族负责，所以西文走西文字体，中文走中文字体。整段字号一样时用"支柱"把每行强制成 字号 × 行高，否则中英文混排的行会比纯中文的行高出几个像素；有比默认字号大的字时不能强制，否则大字的行会和上下行叠在一起，这时支柱只是最小行高，行跟着大字长高（这种段落里中英文混排的行可能高出一点）。光标、上下移动都按每行实际的位置和高度算。
- **编辑**：文字画在画布上，键盘输入交给一个看不见的 `<textarea>`。它负责输入法、组合键、剪贴板和左右移动光标，我们把它的内容和选区同步到文档，自己在画布上画光标和选区。输入框始终跟着光标移动，输入法的候选窗才会出现在正确的位置。
- 上下方向键由我们接管，按真实排版计算；编辑中的撤销走文档的历史，不用输入框自带的。
- 一段连续输入是一步撤销；新建文本后什么都没写就离开，不在文档和撤销历史里留痕迹。
- **保真外观**（`core/src/text-appearance.ts`）：从 PDF 导入的文字除了内容和样式，还带着原文件里每个字的字形和位置。字形按字体存成"字形库"放进资源库，同一个字形只存一份；文本节点只记字形的序号和坐标。没改过的文字按这些字形画，看起来和原文件一模一样。
  - "改没改过"靠指纹判断：生成外观时记下文字和排版参数的指纹，画的时候用当前的值再算一遍，对上了才用。所以无论从哪里改（打字、属性面板、拖宽度），都不会画出过时的样子；改颜色、移动、旋转不影响；撤销回去指纹又对上，原样自动回来。
  - 开始编辑时"解冻"：先等字体加载好，再换成正常排版，并把文本框挪一下，让第一行基线落在原来的位置。什么都没改就退出时换回原样，撤销历史里不留痕迹；改了的话，解冻和这次输入合成一步撤销。
  - 字形库还记着每个字形代表的文字和步进宽度，导出 PDF 时按原字形写出的文字也能被搜索和复制。
- **段落样式**（`core/src/paragraphs.ts`）：用换行分开的每一段可以有自己的对齐、段前段后距、左缩进、首行缩进，也可以是列表的一项（项目符号或编号，0–8 级）。
  - 数据：`paragraphs` 是按段落序号排的数组，每项只记和默认值不同的那几项（默认对齐是节点的 `align`，其余默认为 0、不是列表），没有不同的写成 null，全都没有时省略。
  - 打字时跟着走：按回车分出的新段接着原来那段的样式（列表接着往下排），删掉换行合并的两段用前一段的样式。在段末按回车和在下一段开头按回车得到的文字一样，靠回车之后光标的位置分辨新段接着哪一段。
  - 编辑时改选区碰到的那几段（没选中时是光标所在的一段），没在编辑时改全部段落；碰到全部段落时对齐改的是节点的默认对齐。
  - 列表：Tab / Shift+Tab 升降一级；在空的列表项上按回车、在列表项开头按退格，退出列表。编号同一级连续往下数，里一级、隔了普通段落或项目符号就重新数；样式按层级轮换（1. → a. → i.，• → ◦ → ▪）。
  - 排版：每一段单独排成一个 Skia 段落，按段前段后距从上往下摆（只加在段与段之间，文本框的上下不留）。Skia 的对齐是整个段落共用的、也不支持缩进，所以每段各排各的：左缩进是把这一段往右挪、排版宽度相应减小；首行缩进是段首一个这么宽、不占高度的占位符；空的一段放一个零宽空格，才有一行的高度和光标位置。光标、点击、选区、上下移动都在段内的位置和整个文本的位置之间换算。
  - 列表的符号用这一段第一个字的样式单独排成一个小段落，基线和第一行对齐。每一级缩进 1.8 个字（按整段字号），符号右边缘离文字半个字，所以位数不同的编号按小数点对齐，折行的行和文字对齐（悬挂缩进）。
  - 导出 PDF、SVG 用的是同一份排版结果，段落样式自动带过去；列表的符号写成真正的文字，可以复制。
- 待做：段落样式还没有负数的首行缩进（悬挂缩进）、右缩进、每段自己的行高；打开 PDF 时项目符号还是普通文字，没有还原成列表。复制粘贴时带上样式、上标下标、Home / End 按视觉行移动、表情符号字体、竖排、沿路径排列。文字转轮廓见"对象操作"一节的"生成路径"。

### 打开 PDF 并编辑

按转换式设计：打开时把页面内容转成自己的可编辑对象，改完导出新的 PDF，不覆盖原文件。

导入器在 `packages/io/src/pdf`，分两步，中间只靠一份自己定义的数据（`ir.ts`）打交道：

1. **解释**（`interpret.ts`）：PDF 的页面内容是一段绘图指令。解释器像渲染器一样维护图形状态，把指令"执行"一遍，但不画出来，而是记下页面上最终有哪些对象。指令由 pdf.js 解析；换解析库只需要重写这一步的外壳（`load.ts`）。
2. **生成节点**（`build.ts`）：把对象变成文档节点。文字先在 `paragraphs.ts` 里拼回段落，在 `fonts.ts` 里匹配字体。

pdf.js 模块由宿主传入，导入器本身不依赖运行环境：浏览器里解析在工作线程进行，解析库和它附带的字体、字符映射表在第一次打开 PDF 时才加载；测试在 Node 里跑同一套代码。

已经做到的：

- 每页一个画板，也是幻灯片的一页；页面旋转、裁切框都已换算。1 个文档单位等于 PDF 的 1 点。
- 形状尽量还原成可以直接编辑的样子：矩形（含旋转过的）、圆角矩形、椭圆能认出来，其余是钢笔路径。认形状靠在轮廓上取点，不看路径是怎么构造的，所以各家软件画的圆都认得。
- 图片解码后存成 PNG 放进资源库，是矩形的图片填充。蒙版图片按填充色上色。
- 文字变成可以直接编辑的文本，改之前按原文件的字形显示（见上面文本一节的"保真外观"）：
  - 一行：同一条基线上被拆碎的小段（换字体、换颜色、逐字定位、上标、小型大写字母）接成一行；用字距拉开的词间距补成空格；隔得很远的（表格的两列、项目符号和正文）分开。
  - 一行里和主要样式不同的字（加粗、斜体或换色的词，换了字体的字，小一号的上标和小型大写字母）变成字符级样式，开始编辑之后照样保留；改之前按原字形显示时，换色的字也按自己的颜色画。斜体主要靠字体名认（Times-Italic、Helvetica-Oblique、TeX 的 cmti），解析库常常不给斜体标志。空格的样式不可靠（PDF 里常常没画空格，是按间距补的）：前后的字样式相同时跟着它们，否则用整段的默认样式。
  - 段落：方向、字号、颜色、字体类别和粗细都一样，行距均匀，左右边的对齐方式一致的相邻几行拼成一段，变成固定宽度、自动折行的文本；行高、宽度、对齐方式（左、中、右、两端对齐）都从原文件里量出来。两端对齐的段落里没顶到右边的行、左对齐里多缩进一截的行，当作新段落的开头；中文段首缩进保留成全角空格；居中和右对齐的保留原来的断行。只拼画的顺序上紧挨着的行，上下层次和原文件一样。
  - 字体：按字体名（不认识时按字体描述里的标志）分成无衬线、衬线、等宽三类，换成对应的内置字体，并认出粗细。西文用等宽替代字体，所以换过去之后每行的长度基本不变：一份 TeX 文档里 8 段正文开始编辑后，行数和原文件全部一致。
  - 竖排、描边、没有填充的文字还不能编辑，按原样变成轮廓，节点名就是那段文字。
  - 有的字体把「小」「页」这样的字映射到外形相同的部首码位上，导入时换回普通汉字，搜索和编辑才对得上。
- 透明组变成带不透明度和混合模式的编组；只有一个对象的组直接把透明度给那个对象。
- 第一个画的东西如果是铺满整页、不透明的纯色矩形（演示软件导出的 PDF 常这样画底色），它变成画板的背景色，而不是一个盖住整页的矩形。
- 裁剪：能化简的先化简，其余的还原成蒙版组。
  - 对象完全在裁剪范围里：裁剪不起作用，忽略；完全在外面：对象看不见，不导入。
  - 矩形裁剪矩形：直接算出剩下的部分。
  - 图片被矩形、圆、圆角矩形或任意形状裁剪（"图片放在框里"）：变成填了图片的那个形状，图片在里面缩放、移动到原来的位置。
  - 用形状裁剪后铺满颜色或渐变：变成那个形状本身。
  - 别的情况变成按形状遮的蒙版组，裁剪的形状在最上面当蒙版。同一个裁剪下连续画的对象放进同一个组，和 Illustrator 的剪切组一样。先后设了好几次裁剪（取交集）时，一个形状套一层，套起来就是交集，不用近似。
- 线性和径向渐变还原成渐变填充：渐变的几何从它自己的坐标换到形状的本地坐标，再换成相对外框的位置。图案里的渐变相对页面（或者所在表单）的坐标，和当前的坐标变换无关。径向渐变被拉成椭圆时还原成椭圆；两个圆同心时把色标按半径重新排，圆心不同（焦点偏移）时近似成同心的。两头不延伸的渐变用透明的首尾色标表示。半透明编组折算到对象上时，透明度乘进色标。铺满整页的渐变变成画板的渐变背景。
- 软蒙版（透明蒙版）：渐变的透明度常常写成一个软蒙版，蒙版里是一个几何完全相同的灰度渐变，认出这种写法时把蒙版的亮度乘进色标的透明度（我们自己导出的 PDF 也是这样写的）。别的软蒙版还原成按亮度或透明度遮的蒙版组：蒙版里画的东西转成节点放在最上面，同一个蒙版下连续画的对象放进同一个组。
- 可选内容（图层）里关掉的不导入；看不见的文字（扫描件的识别层）不导入。
- 没法完全还原的地方按种类计数，导入完告诉用户：读不出形状的裁剪、读不出内容的透明蒙版（忽略）、网格渐变和描边、文字上的渐变（改成平均色）、图案填充（去掉）、没有内嵌字体的文字（只能用匹配的字体重排）、读不了的图片。
- PDF 是不可信的输入：坐标和像素数据都检查范围，关闭解析库的动态代码生成，限制页数、对象数和单张图片的大小。

还没做的：

- **页数上限**：文档本身已经很轻（一份 TeX 文档 6 页正文约 0.4MB；上一版按轮廓存时 10 页要 50MB），但字形还是按路径画的，几十页的字同时出现在屏幕上时每一帧都要画一遍。所以导入时仍有总量上限（默认 150 万个点，大约三十多页密排的正文）。以后改成用原文件内嵌的字体直接画字（pdf.js 能交出字体文件，Skia 能按字形编号画），上限可以再放宽很多。
- 改字之后换成我们的字体：内嵌字体里有的字也不会继续用原字体。要做到这一点得把内嵌字体的字符映射改写成 Unicode，再交给排版引擎。
- 上标、下标只保留了小字号，开始编辑之后不再抬高或降低。
- 表格、多栏、项目符号的悬挂缩进只做了最基本的处理：拼段落不会跨列，但也不会还原成表格或列表。
- 图案填充、网格渐变。
- 软蒙版的背景色（BC）和转换函数（TR）没有用上：绝大多数文件用的是默认值。
- 有密码保护的 PDF。

### 导出 PDF

文件菜单里的"导出 PDF"：每个画板一页，先是幻灯片（按播放顺序），再是其余的画板。1 个文档单位是 1 点，和打开 PDF 时一致，打开再导出尺寸不变。

渲染器多了一个"PDF 后端"（`renderer/src/pdf.ts`）：和屏幕渲染一样遍历节点树，只是写的是 PDF 的绘图指令。PDF 文件本身的写法（对象、内容流、字体、图片）在 `io/src/pdf-export`，不依赖渲染引擎。原计划自己编译带 PDF 后端的 Skia，实际用不着：要写的东西不多，自己写还能控制文字怎么写。导出的代码单独打包，第一次导出时才加载。

- **形状**写成路径，填充、描边、不透明度、16 种混合模式都是 PDF 原生支持的。Skia 画椭圆和圆角用的圆锥曲线换成三次曲线；布尔组写运算结果。纯色填充加不透明的描边合成一条"填充并描边"指令；描边半透明时不能合，PDF 规定这条指令里的描边直接盖掉填充，而不是叠在上面。
- **透明组**：需要先合成再整体透明或混合的（编组、又有填充又有描边的形状、文字）写成 PDF 的透明组，和渲染器的离屏层一一对应，重叠处不会变深。
- **蒙版组**：形状模式写成裁剪路径；透明度、亮度模式把蒙版画进一个表单当软蒙版（Alpha / Luminosity），内容先合成成一个透明组再整体套上去——软蒙版作用于每一次绘制，不先合成的话内容重叠处会和画布上不一样。
- **渐变**写成 PDF 原生的线性、径向渐变，几何直接写在节点的本地坐标里；色标拼成分段的插值函数，硬过渡就是分段的边界；椭圆的径向渐变在裁好形状之后把坐标压扁再画。色标有透明度时，同样几何的灰度渐变当软蒙版。
- **图片**裁成形状的轮廓放进去，铺放方式、画面内的缩放平移和画布上一样。没调整过的 JPEG 原样放进去（拍摄方向不正的、CMYK 的除外）；其余的解码成像素，调色和模糊先在像素上做好。完全透明的像素换上旁边的颜色，不然阅读器缩放图片时半透明的边缘会发黑。
- **文字是真正的文字**：
  - 我们排版的文字：把用到的字形从字体里做成子集嵌进去（字形编号不变），每个字按排版引擎给出的位置写。大多数字之间共有的那份距离（字距、中文两端对齐拉开的距离）用字距指令写，其余的差额写成调整量。排版结果里只有字形编号，认不出用的是哪个字体文件，所以拿这段字在字体里的字形编号和每个候选文件逐一比对。
  - 字符级样式：粗体、斜体用各自的字体文件，颜色按段写；字体没有斜体文件时（中文）照排版引擎的做法把字形斜切，没有粗体文件时用同色描边描粗。
  - 下划线和删除线排版结果里没有，自己画成横线，照 SkParagraph 的做法：粗细取字体里记的下划线粗细（只有删除线时取删除线粗细），线的中心在这一行的基线往下"字体里记的位置"处。这里的基线要用排版引擎行信息里没取整的那个：画字时基线取整到了整数，画线时没有。原来按取整后的基线、把线的上沿放在那个位置，导出的线比画布上低了大约一个线宽（28 号字低 1.5 个单位），做文字转轮廓逐像素比较时发现，改过之后 PDF、SVG 一起对上了。
  - 模拟粗体：排版结果里的 `fakeBold` 在 0.42 版里和 `fakeItalic` 一样没有填，之前导出 PDF、SVG 时中文的模拟粗体丢了（画出来是常规体）。现在按排版引擎的规则推断：要的字重至少 600，并且比字体文件重 200 以上。描粗的宽度用 Skia 的公式（9 号字是字号的 1/24，36 号字是 1/32），和 FreeType 的描粗（字号的 1/24）比过，前者和画布更接近。
  - 画布上用 WOFF2 字体，嵌入 PDF 用同一个文件的 WOFF 版本：WOFF2 解压要带一个很大的解码器，WOFF 用现成的 zlib 就行。WOFF 文件只在导出时下载，但正式构建因此从 26MB 增加到 41MB。
  - 两者本该是同一份字体，但 fontsource 有的分片两边的字形编号不完全一样：思源黑体放标点的那个分片里，全角冒号在 WOFF2 里是 296 号字形，在 WOFF 里是 291 号，直接用排版结果的编号会写出别的字（导出 SVG 时发现的，之前导出的 PDF 里全角冒号是错的）。现在写字之前按字符映射表对一遍：一个字形正好是某个字符在排版字体里的字形时，换成这个字符在嵌入字体里的字形；连字、变体这类查不到的保持原样。
  - 认字体文件：先比按区间算出来的那几个分片，再比这几个家族所有已加载的分片（有的字不在任何分片声明的区间里，排版引擎是在别的分片里找到它的）。都对不上时整段文字画成图片，不再随便挑一个文件——字形编号在别的文件里是别的字。
  - 从 PDF 导入、没改过的文字：字形库里的轮廓做成 Type3 字体，每个字放在原来的位置，样子和原文件一样。
  - 两种都带字符对照表，可以搜索、选中和复制；原文件里映射到部首码位的字（「小」「页」）换回了普通汉字，导出的 PDF 比原文件还好搜。
- 不知道怎么写成矢量的节点（扩展的节点类型、取不到字体文件的文字）画成两倍图放进去。
- 页面边长超过 200 英寸（PDF 阅读器的上限）时整体缩小，再用 UserUnit 告诉阅读器实际大小。

验证：把导出的 PDF 用 pdf.js 渲染，和画布逐像素比较。一份浏览器生成的中英文 PDF 打开后再导出，差异明显的像素占 0.01% 和 0.02%；一页 TeX 正文 0.65%；一张带混合模式、透明编组、调色和模糊的图片、中英文文字的测试页 0.63%，全部在文字上（画布上 Skia 画的字比字体轮廓本身略细，PDF 里是字体原样），文字以外只有 0.003%。导出的 PDF 再用我们的导入器读回来，还是同样的形状、编组、可以编辑的文字和画板底色。

还没做的：

- 有的阅读器（比如 pdf.js）复制文字时，会把超过约 0.1 个字的字间距当成词与词的间隔，补上空格；中文两端对齐拉开得比这多时，复制出来是"导 出 文 字"。
- 嵌入的是我们的字体：改过的文字不会用回原文件的字体。
- 画板以外的对象不导出。PDF/A、PDF/X、超链接、书签、无障碍标签都没有。

### 导出 SVG

文件菜单里的"导出 SVG…"：可以导出选中的对象、当前画板，或者全部画板（每个画板一个 SVG 文件，按幻灯片顺序编号，打包成一个 ZIP）。1 个文档单位是 SVG 的 1 个用户单位（CSS 像素）。打开对话框时有选中的对象就默认导出它们，否则用上次的选择（记在浏览器里）。

- **选中的对象**合成一个 SVG 文件，画面正好框住它们（描边留出余量），每个对象按它在画布上的位置摆：父节点的变换算进去，父节点的不透明度、混合模式、蒙版不算。选区里只取最外层的对象，按层序从下到上画。画板以外的对象也可以这样导出。

渲染器的"SVG 后端"（`renderer/src/svg.ts`）和 PDF 后端一样遍历节点树，写的是 SVG 元素；元素树、转义、网页字体这些写法上的事在 `io/src/svg-export`，字体子集、WOFF 封装、读字形轮廓在 `io/src/font`，都不依赖渲染引擎。排版结果拆成一段段字（`renderer/src/text/shaped.ts`）、图片调整烤进像素（`renderer/src/bake.ts`）是两种导出共用的。

- **形状**：矩形、椭圆写成 `<rect>`、`<ellipse>`（在设计软件里打开还是矩形、椭圆），其余写成路径。填充、描边、不透明度、混合模式直接写在元素上；只有一个元素时不另包一层 `<g>`。SVG 元素上的不透明度本来就是"先合成再整体透明"，和画布的离屏层一致，不用像 PDF 那样另做透明组。
- **混合模式**写成 CSS 的 `mix-blend-mode`，16 种一一对应。
- **渐变**写成 `linearGradient`、`radialGradient`，几何用节点的本地坐标（`userSpaceOnUse`）；椭圆的径向渐变用 `gradientTransform` 压扁；色标的颜色和透明度分开写，SVG 也是分开过渡的，不用软蒙版。
- **蒙版组**：按形状裁剪写成 `<clipPath>`；按透明度、亮度遮写成 `<mask>`，用 `mask-type` 区分，范围取蒙版的外框再放宽一圈。
- **图片**放在 `<defs>` 里，用 `<use>` 摆进形状，再按形状的轮廓裁剪；同一张图只放一份。没调整过的 PNG、JPEG 原样放（拍摄方向不正的、CMYK 的 JPEG 除外），其余的把调色和模糊烤进像素、编码成 PNG。
- **文字**两种写法，导出时选：
  - **保留为文字**：一个文本节点是一个 `<text>`，每段字（同一个字体文件、同一种样式）是一个 `<tspan>`。每个字按排版引擎给出的位置摆（`x` 是一串数），所以不管看的人那边怎么排版，位置都和画布上一样；选中、复制、搜索时是连着的一整段，在设计软件里是一个文本对象。用到的字体做成子集（只留用到的字形，去掉字形名），封装成 WOFF 内嵌在 `@font-face` 里；家族名、字重、正斜体照实写，装了同样字体的设计软件里可以直接改字。中文字体切成很多分片，每个分片是同名的一条 `@font-face`，用 `unicode-range` 写明它负责哪几个字。字体没有斜体文件时写成 `font-style="italic"`，浏览器同样把字形斜切四分之一，和排版引擎一样（在 Chrome 里比过，和画布的差异与写进 transform 时相同）；同一个家族还用到了真正的斜体文件时，浏览器会拿那个文件来画，这时斜切写进 `transform`，单独成一个 `<text>`。没有粗体文件时用同色描边模拟。下划线、删除线画成矩形。折行处排版引擎没画的空格补在行尾，复制出来词不会粘在一起。
  - **转成轮廓**：每段字是一条路径，在哪里打开都一样。字形轮廓从字体文件的 glyf 表里读（渲染引擎的默认构建取不到字形的路径）。
  - 从 PDF 导入、没改过的文字按原字形画成路径；保留为文字时上面再叠一层看不见的文字，可以搜索和复制，和扫描件 PDF 的识别层一样。字形之间没画出来的字（多半是空格）从节点的文字里按顺序找回来。
- 不知道怎么写成矢量的节点（扩展的节点类型、取不到字体文件的文字）画成两倍图放进去。

验证：把导出的 SVG 用浏览器画出来，和画布逐像素比较。一张带圆角描边、旋转、混合模式、线性和椭圆径向渐变（含硬过渡、半透明色标）、透明编组、三种蒙版、调色模糊的图片、中英文混排（字符级粗体、斜体、下划线、删除线、两端对齐、旋转的衬线斜体、中文模拟斜体）的 1280 × 720 测试页：差异明显的像素占 0.98%（保留为文字）和 0.68%（转成轮廓），文字以外只有 0.085%，都在边缘的抗锯齿上；同一页导出 PDF 再打开（文字按原字形显示）后导出 SVG，差异 0.19%。

还没做的：

- 导出画板时，画板以外的对象不导出（选中它们用"选中的对象"可以导出）。
- 模拟斜体单独成 `<text>` 的那种情况（见上），以及从 PDF 导入的、方向不同的几段字，复制时会断开。
- 字形编号对不上、又查不到字符的字形（连字、变体）还是按排版结果的编号写，在那几个字形编号不一致的分片里可能是错的。
- 渐变描边（文档本身还没有）。
- 只在 Chromium 内核的浏览器里比较过，Safari、Firefox 以及 Illustrator、Figma、Inkscape 打开的效果还没有测。

### 动画

PPT 式的幻灯片动画，用 HTML5 实现。

**数据模型**

- 每页幻灯片有一个切换效果（进入这一页时怎么切过来），和一张按顺序排列的动画列表，相当于 PPT 的动画窗格。两者都存在画板的 `deck` 里。
- 每条动画作用于这一页上的一个对象，记录效果、开始方式（单击时、与上一动画同时、上一动画之后）、时长、延迟、方向；动作路径还记着路径。
- 时间安排是纯函数：把动画列表排成若干"步"，第 0 步进入页面后自动播放，之后每单击一次播一步。第一条动画是进入效果的对象，一开始是隐藏的。

**效果库**

- 每个效果是一个注册到效果库里的函数：输入对象的位置、页面尺寸和方向，输出 Web Animations API 格式的关键帧。新增效果只需注册一个函数，界面上的效果列表直接来自注册表。
- 已有：进入和退出各六种（出现 / 消失、淡入淡出、飞入飞出、浮入浮出、缩放、擦除），退出效果就是进入效果倒放；强调四种（脉冲、旋转、摇晃、闪烁）；动作路径四种（直线、弧线、圆形、自定义路径）。
- 页面切换：无、淡入淡出、推入、缩放、平滑。

**动作路径**（`core/src/motion.ts`，画布上的显示和修改在 `editor/src/motion-handles.ts`，画路径的工具在 `editor/src/tools/motion-path.ts`）

- 对象沿一条贝塞尔路径移动，路径存在这条动画的 `path` 里，用钢笔路径的锚点模型（一个子路径）。坐标是幻灯片坐标里相对对象中心的位移，起点通常是 (0, 0)。
- 播放：路径按弧长等分取点（大约每 6 个单位一个，8 到 240 个），排成一串 `translate` 关键帧，每一小段走的距离一样，速度是匀的，整条动画再用缓入缓出。用 `translate` 而不是 CSS 的 `offset-path`，是因为导出视频时按计算出来的样式逐帧读画面，`translate` 一定读得到；播放器和录像都不用改。
- 播完对象停在终点（和 PPT 一样）。同一个对象有好几条动作路径时，按列表顺序后一条从前一条的终点接着走；之后的飞出、浮出这类平移也从那里出发，飞出幻灯片要走多远按挪过之后的位置算。这一步在排时间的纯函数里做，关键帧整体平移。
- 预设路径按幻灯片大小定尺寸：直线向右走四分之一宽，弧线向右下鼓，圆形绕一圈回到原处。自定义路径：从动画列表里选"自定义路径…"，换成画路径的工具，像钢笔一样单击加点、拖出曲线，回车结束，Esc 取消；起点固定在对象现在的位置（已有动作路径时是最后一条的终点）。钢笔工具和它共用一套画法（`editor/src/tools/path-drawing.ts`，从原来的钢笔工具里拆出来的）。
- 修改：选中有动作路径的对象时，画布上把它的每条路径画成虚线（白底上叠一条主题色的虚线），起点是绿色三角，终点是红色方块。锚点和控制柄可以拖：拖锚点连同两根控制柄一起挪，拖平滑锚点的一根控制柄时另一根反向跟着转。路径的手柄比缩放控制柄优先点中。一次拖动是一步撤销。动画列表里可以反转路径方向。
- 验证：单元测试检查按弧长等分（直线上间距相等，弧线上各段相差不到 2%）、圆形闭合且长度接近 2πr、反转、两条路径和飞出的衔接、文件校验，以及在编辑器里加预设路径、画自定义路径（相对出发点存）、第二条接着第一条画、拖终点和控制柄（一步撤销）、反转。在 Chrome 里实测：加弧线、拖终点、画一条接着的自定义路径，进演示模式单击两次，对象先沿弧线走到终点，再从那里沿自定义路径走，停的位置是两条终点相加；刷新页面后草稿里的路径还在。

**HTML5 播放器**（`packages/player`）

- 一个完全自给自足的函数，不依赖文档模型和编辑器的任何代码，用浏览器原生的 Web Animations API 播放。
- 它吃的是"编译好"的数据：每一页上的每个对象已经写成一段 SVG（和导出 SVG 是同一套代码，文字保留为文字），每条动画已经算成关键帧和时刻。动画由浏览器原生执行。写不成 SVG 的对象退回成由 Skia 渲染的透明背景图片。
- SVG 图层直接放进网页里（不是 `<img>`），所以放大不糊，文字可以选中、复制，也能被网页的查找搜到；拖动鼠标选字时不翻页。所有图层用到的字体做成一份 `@font-face`，播放器放进网页。
- SVG 里渐变、裁剪、蒙版、图片的 id 由播放器每次放进网页时换成唯一的前缀：平滑切换时前后两页、淡出的残影里会有同样的图层，id 重复的话，引用会指到已经隐藏的上一页，内容就看不见了。同样的内容得到一模一样的 SVG，平滑切换靠这一点判断"内容变没变"，没变就不做交叉淡化。
- 每个图层是三层嵌套的元素，各管一件事：最外层负责整体平移、混合模式和显隐；中间层把图层摆到幻灯片上的固定位置；最内层做以图层中心为原点的缩放、旋转、透明度和裁剪。
- 混合模式直接用 CSS 的 `mix-blend-mode`，取值和文档里的 16 种一一对应。
- 操作：单击或方向键前进，动画进行中再按一次直接播完；左方向键回到上一页；Esc 退出。

**演讲者视图**（`apps/web/src/present/PresenterView.tsx`、`popup.ts`）

- 备注：没选中对象时，属性面板里这一页的设置下面有"演讲者备注"，纯文字。打字时直接写进文档（`setSlideNotes`），从点进去到离开是一步撤销；输入框里的按键不会触发画布的快捷键。备注只在编辑器和演讲者视图里用，不写进播放器的数据，导出的网页里没有。打开文件时校验备注只能是文字。
- 演示时右上角的按钮打开演讲者视图：一个单独的浏览器窗口（和 Google 幻灯片一样），主窗口照常全屏给观众看，演讲者视图拖到自己的屏幕上。窗口要在用户点按钮的那一下打开，否则会被当成广告弹窗拦掉；被拦了会提示允许弹窗。
- 窗口里的界面用 React 的 portal 渲染进去，和主窗口共用状态和语言包；主窗口的样式表（开发时是 `<style>`，构建后是 `<link>`，改成绝对地址）和写在 `<html>` 上的主题变量搬过去。窗口是 about:blank，同源，图片的临时地址也能用。
- 显示：左边是观众此刻看到的这一页，右边是下一页（进入时的样子）和这一页的备注（字号可以调，记在浏览器里），上面是计时（从演示开始算，可以暂停、清零）和时钟，下面是上一步、下一步。
- 同步：翻页都交给主窗口里观众看的那个播放器，演讲者视图跟着它的状态（第几页、第几步）走，两边不会对不上。"当前页"和"下一页"各是一个只用来看的播放器（`player/src/settle.ts` 的 `settlePlayer`）：跳到那一页，一步步播到观众那边的步骤，每一步直接播完，只显示播完的样子；不响应点击和按键。演讲者视图窗口里的按键在文档的捕获阶段统一处理（→ ↓ 空格 回车 PageDown 前进，← ↑ PageUp 退格 后退，Home、End，Esc 结束演示），点当前页也是前进。关掉这个窗口只是收起演讲者视图；结束演示时窗口一起关掉。
- 验证：单元测试检查 `settlePlayer`（按播放器的翻页规则模拟：跳页、往前播、退回这一页开头、不会翻过头）、备注连续输入是一步撤销、备注的校验。浏览器里实测：备注的输入、退格不删画布上的东西、一步撤销；弹窗被拦时的提示。内置浏览器不让自动化的点击开弹窗，所以演讲者视图本身是把 `window.open` 临时换成同源 iframe 的窗口来测的，走的是同一套代码：标题、样式、计时的暂停清零、备注字号、按按钮和方向键翻页时两边的页码和步骤一致（"当前页"里对象停的位置和观众那边逐像素相同的平移量）、最后一页显示"演示结束"并禁用前进、Esc 结束演示。真正的弹出窗口还没有在浏览器里实际点开测过。

**平滑切换**

- 两页上 `lineageId` 相同的图层被当成同一个对象，从旧的位置、大小、旋转补间到新的；内容变了就同时交叉淡化。
- 新页面上没有的对象原地淡出，旧页面上没有的对象淡入。
- "复制幻灯片"会保留 `lineageId`，所以复制一页再挪动对象，就得到一次平滑切换。

**导出**

- 导出成单个 HTML 文件：SVG、字体、图片都内嵌，播放器的源码直接写在文件里，不引用任何外部资源，断网也能播。一页带图片、渐变、蒙版和中英文的测试幻灯片，导出的网页 114KB；原来每个对象画成两倍图时，光图片就有 413KB。
- 播放器的源码是从正在运行的那个函数上取下来的，所以导出的网页和应用内预览跑的是同一份代码。代价是这个函数必须完全不引用外部变量，这一点写在了函数的注释里。

**导出视频（MP4、GIF）**

文件菜单里的"导出视频…"。全在浏览器里完成，不需要服务器。

- **画面由播放器录下来**（`player/src/record.ts`），不另外实现一遍动画。播放器有一个虚拟时钟模式：时间不自己走，由 `advance()` 推进，定时器和 Web Animations 的动画都按这个时钟走（动画先暂停，再按时钟设置进度，到头了让它结束，后面接着发生的事照常进行）。播放器放在屏幕外面播放，每推进一帧，从它的元素上读出每个图层此刻的位置、透明度、裁剪、混合模式和显隐——这些值是浏览器按动画算好的，和演示时屏幕上的一样——再把图层的图片按这些值画到画布上。所以动画、五种页面切换、平滑切换的配对和交叉淡化都和演示时一致。播放器的元素带着 `data-shiba` 标记，录像靠它们找元素。
- **图层是图片**：录像要把图层画到画布上，内联 SVG 里的文字用的是网页里的字体，画不到画布上，所以导出视频时图层渲染成图片，倍率按画面放大的倍数再留 25% 余量。渐变背景在播放器里是 CSS 渐变，录像时用画布的渐变按同样的几何画。
- **自动播放**：单击才开始的动画，在上一步播完后等一会儿（默认 1 秒）自动开始；一页的动画都播完后停一会儿（默认 3 秒）再翻页，最后一页停完结束。
- **MP4**：浏览器自带的编码器（WebCodecs）编成 H.264，按画面大小和帧率挑最低够用的等级，依次试 High、Main、Baseline；每两秒一个关键帧；编码器排队太多时等它跟上。装箱（`io/src/video/mp4.ts`）是自己写的：索引在前、数据在后，可以边下边播；编码器重排了帧（B 帧）时写出显示偏移，用编辑表对齐起点。
- **GIF**（`io/src/video/gif.ts`）：和上一帧一样的帧不另写，只加长上一帧的停留时间；之后每一帧只写变了的矩形，矩形里没变的像素写成透明，静止的部分不会重新量化、不会闪；每一帧自己的调色板（中位切分 255 色）加误差扩散抖动，颜色不超过 255 种时原样保留不抖动。
- 默认 1920 × 1080（按第一页的比例缩放，长边不超过 1920、短边不超过 1080）、30 帧；可以选 720p、60 帧。GIF 默认长边 960、15 帧。设置记在浏览器里。导出时提示里显示进度，可以取消。录制和编码的代码单独打包，第一次导出时才加载。
- 浏览器没有 WebCodecs（较早的 Safari）时 MP4 不能选，GIF 照常可以导出；有 WebCodecs 但不支持 H.264 时提示改用 GIF。

验证：一份三页的测试稿（飞入、擦除、脉冲、渐变背景、正片叠底，推入和平滑切换），720p 30 帧 7.3 秒的 MP4 在 Chrome 里 1.4 秒导完，588KB；用 `<video>` 解码，每页静止时的画面和画布的平均差异 1.3–1.6（0–255），是 H.264 的压缩误差；动画中途的画面逐一看过。同一份 GIF（640 宽 15 帧）57 帧、463KB，最后一帧和画布的平均差异 0.37。1080p 的 MP4 是 1.2MB。

**待做**

- 视频导出只在 Chrome 里试过，Safari、Firefox 还没有测。
- 视频里没有声音；幻灯片的切换时刻不能单独设置（只有统一的停留时间）。
- 按段落或逐字播放的文本动画、重复和自动翻页。
- 动作路径：不能沿路径转向；画布上不能加、删锚点，不能在尖角和平滑之间切换，不能整条拖动；不显示对象在终点的样子；平滑切换不考虑动作路径挪过的位置。
- 触屏滑动翻页。
- 演讲者视图：见上面"演讲者视图"里的还没做的部分。
- 对象被编进组之后，它原有的动画会失效（动画只能作用于幻灯片的直接子对象），界面上会标出来，但不会自动转给所在的组。

### 渐变

- **数据**（`core/src/gradient.ts`）：渐变是形状和画板背景的一种填充，和纯色、图片并列。有线性和径向两种，记起点、终点和一串色标。起点终点按节点外框的相对位置记，形状缩放时渐变跟着缩放；但渐变在节点的本地坐标里画：线性渐变的色带总是垂直于起止点的连线，径向渐变是正圆，可以再按一个比例压扁成椭圆。这和 PDF、SVG 的渐变一一对应，导入导出不失真。
- **过渡**：颜色和透明度分开直线过渡，超出两头的部分延续首尾的颜色。两个色标在同一位置就是硬过渡（条纹）。
- **编辑**：外观面板的填充可以在纯色、渐变、图片之间切换，纯色和渐变互换时保留颜色。渐变编辑器有类型、角度（按画面上看到的算，色带长度让两头的色标正好落在外框的对角上，和 CSS 一样）、反向，以及一条色条：拖动色标改位置，点空白处加色标（颜色取那里原本的颜色，加上去看不出变化），选中的色标改颜色、不透明度或删掉。
- **幻灯片背景**：网页播放器里用 CSS 渐变画，色标位置换算到 CSS 的色带上；平滑切换时渐变背景不做颜色过渡，直接换。
- **在画布上拖动**：起点终点、径向渐变的压扁比例都可以在画布上直接拖，见"对象操作"一节的"在画布上调整填充"。
- 待做：角度渐变（锥形）、描边和文字的渐变。

### 图片

- **图片是填充，不是节点**：图片作为形状的一种填充存在，所以矩形、椭圆、钢笔路径、布尔组都天然是图片的蒙版。放一张图片到画布上，得到的是一个用它作填充的矩形。
- **铺放方式**：铺满（保持比例，裁掉多余）、适应（完整显示，留空处透明）、拉伸。
- **资源库**：图片字节存在资源库里，按内容的 SHA-256 寻址。同一张图片导入多次只存一份；节点只记资源 id。
- **导入**：工具栏按钮、拖进画布、粘贴。渲染引擎能直接解码 PNG、JPEG、GIF、BMP；其他格式（WebP、AVIF 等）由浏览器转成 PNG 再存。
- **大图**：长边超过 4096 像素的图片在导入时缩小。解码后的图片整张放在内存和显存里，不限制的话几张相机原图就能拖垮画布。这是临时做法，会损失原图分辨率；正式方案是保留原图、编辑时用缩小的代理图、导出时再用原图。
- **调整**：非破坏性，只存一组参数，原图不动。调色有亮度、对比度、饱和度、色温、色调、色相，合成一个颜色矩阵交给 GPU；其中亮度、对比度、饱和度、色相的算法与 CSS 滤镜的定义一致，以后导出成网页可以直接用 CSS 实现。模糊只作用于图片内容，形状的边缘保持清晰。
- **画面内缩放与平移**：在铺放方式之上再把图片放大、移动它在形状里的位置，相当于简单的裁剪。
- 画面内的缩放平移也可以在画布上直接拖，见"对象操作"一节的"在画布上调整填充"。
- **曲线、锐化、滤镜预设**（数据在 `core/src/curves.ts`、`core/src/image-presets.ts`，渲染在 `renderer/src/image-look.ts`）：
  - 曲线：一条总曲线（RGB）加红、绿、蓝各一条，先过通道自己的再过总曲线。控制点之间用单调三次插值（Fritsch–Carlson），曲线不会冲过相邻两点的高度，拖一个点时别处不会意外鼓起来；两端以外是平的，和 Photoshop 一样。存在图片填充的 `curves` 里，变回直线的通道不存。
  - 锐化：反锐化掩模，原图减去模糊后的样子，把差值按强度加回去（强度 0–200%，100% 是细节的反差加一倍）。半径和模糊一样用文档单位，画布上缩放到多少看到的都是导出 1 倍时的样子。存在调整参数的 `sharpen`、`sharpenRadius` 里（可选，省略是不锐化、半径 1）。
  - 滤镜预设：黑白、高反差黑白、深褐、复古、胶片、褪色、冷调、暖调、鲜艳九个，每个是一组调色参数加曲线，作用在原图上，再按强度（0–100）和原图混合。文件里只记预设的 id 和强度（`filter`），所以预设发布之后不能再改，要改效果就加新的 id；不认识的 id（更新的版本加的）当作没有滤镜。图片面板里每个预设一个缩略图，是这张图套上这个预设的样子（`Editor.imagePreview`），按图片缓存。
  - 渲染：颜色矩阵做不了这几样，用一个 SkSL 着色器包住图片着色器。顺序是锐化 → 滤镜 → 自己调的颜色 → 自己调的曲线（和 Lightroom 一样，曲线在基本调色之后）。曲线算成 256 × 2 的查找表当子着色器（第一行是滤镜的曲线，第二行是自己调的），线性取样；锐化在着色器里按 5 × 5 的高斯权重取样（间隔是半径），算出模糊的样子。只调了颜色、没有这几样时不用这个着色器，颜色还是走颜色矩阵，以前的文件画出来一点不变。CanvasKit 的默认构建带 SkSL，WebGL 的画布和 CPU 的离屏画布都能用。
  - 导出 PDF、SVG（以及网页、视频，它们用 SVG 图层）时用同一个着色器把效果烤进像素（`bake.ts`），锐化的取样间隔换算成图片像素。
  - 验证：在 Node 里画几种灰阶和色块，检查曲线（反相、通道曲线和总曲线的先后、曲线在调色之后）、锐化（边缘两侧的反差变大、远处不变、半径大影响宽）、滤镜（黑白三通道相等、强度 50 在中间、强度 0 和不认识的预设等于没有）；烤出来的像素和画布上画的最多差 1 个色阶。在 Chrome 里实测：预设缩略图、强度、在曲线上加点拖动（一步撤销）、通道曲线、双击删点、锐化都在 WebGL 画布上正常；滤镜、曲线、锐化、调色一起开着时导出 SVG（烤好的图片）和导出 PNG 逐像素完全一样。WebGL 画布上着色器用的是半精度，和 CPU 导出的只目测比较过。
- 待做：本地抠图（先不做）、在 Worker 里解码。曲线编辑器没有直方图，控制点不能用键盘移动；滤镜不能导入 .cube 之类的 LUT 文件。

### 组件与样式

可以反复用的东西：组件（一组对象做成主组件，到处放它的实例，改主组件时所有实例跟着改）、颜色样式、文字样式。数据和同步在 core（`components.ts`、`styles.ts`），命令在 `editor/src/commands/component.ts`、`style.ts`，界面是左栏的"资源"页、属性栏的"组件"面板，以及外观、文本面板里的样式选择。

**整理器**（`core/src/store.ts`）：文档存储多了一个钩子，每次事务的修改做完、记进撤销历史之前调用，在同一个事务里补上派生的修改。样式和组件的一致性都靠它：改一个颜色样式连同所有链接它的对象、改主组件连同所有实例，都是一步撤销。撤销、重做是整体换回快照，不再调用整理器。整理器拿得到"这次事务里用户自己改了什么"（不含整理器补的），用来分辨用户的手动修改。存储也多了 `replace`（整个换掉一个节点，可以去掉字段），同步时要删字段（比如主组件去掉了蒙版）。

**颜色样式、文字样式**

- 样式记在文档的根页面上（`PageNode.colorStyles`、`textStyles`），每个样式有 id、名字和值。文字样式的值是字体、字号、字重、行高、字距、斜体、下划线、删除线，不含颜色，和常见的设计软件一样。
- 对象链接样式时只多记一个样式 id（`SolidFill.colorStyle`、`Stroke.colorStyle`、`TextNode.textStyle`），值照常存着，所以渲染、导出、打开 PDF、播放器都不用认识样式；旧文件没有这些字段，不用迁移。链接的 id 不是排版参数，不进保真外观的指纹。
- 改了样式：整理器把所有链接它的对象改成新的值。文字样式改了只换整段的默认样式，单独设过样式的字（比如加粗的一个词）保留；新的默认样式和单独设的一样时，那一项从区间里去掉。删了样式：链接断开，值留着。
- 对象上链接着样式、值却和样式对不上，说明用户手动改过（改了颜色、改了整段的字号）：整理器断开链接。所以界面上所有改颜色的地方都不用专门处理链接。只改了文字里的几个字（字符级样式）不算，链接还在。
- 给文本套用文字样式时，整段换成样式的值，单独设过这几项的字也一起换掉；套颜色样式时文本整段换色。
- 界面：左栏"资源"页列出颜色样式（色块点开改颜色，拖动取色器是一步撤销；单击名字套用到选中对象的填充，双击改名）和文字样式（单击套用，双击改名，可以用选中的文字更新样式）。外观面板的填充、描边，文本面板的文字颜色旁边有颜色样式菜单：套用、用当前颜色新建；链接了样式时显示样式名和断开按钮。文本面板顶上可以选文字样式（选"无"断开），或者用这段文字新建一个。

**组件**

- 主组件是带 `component` 标记的编组，子节点就是组件的内容；实例是带 `instanceOf`（主组件 id）的编组，子节点是主组件内容的真实副本，每个副本用 `source` 记着它对应主组件里的哪个节点。副本是普通节点，所以渲染、导出 PDF / SVG / 网页 / 视频、命中、选中、文字编辑、平滑切换都不用认识组件。原计划的 `instance` 节点类型（实例不存副本、画的时候展开）要让每个后端都学会展开，还选不中实例里的东西，没有采用。
- 同步：主组件里有东西改了（整理器顺着每个改动往上找所在的主组件），它的每个实例照着改：没有的副本补上，主组件里删掉的删掉，顺序（分数索引）直接抄主组件的。一样的副本不重写，渲染缓存还按"是不是同一个对象"判断。
- 覆盖：用户直接改了实例里的副本（换颜色、改文字、隐藏），整理器把改了的属性名记进副本的 `overrides`，以后同步时这些属性保留自己的值；改回和主组件一样时自动去掉。文字、字符样式、段落样式、保真外观按字的位置记，改了其中一项就当四项都改了，免得主组件的区间套到对不上的文字上。
- 实例自己（根节点）的位置、大小、不透明度、混合模式、名字都是它自己的；只有蒙版方式跟着主组件。没起名的实例显示主组件的名字。
- 实例改大小是整体缩放（用户 2026-11-27 选的）：缩放写进实例根节点的变换矩阵（`editor/src/resize.ts`），描边、圆角、字号按比例变，副本的几何始终和主组件一样，所以缩放过的实例照样同步。这是"缩放只改几何"的唯一例外。位置与大小面板按画布上的实际大小显示和输入。
- 嵌套：主组件里可以放别的组件的实例。同步一层一层传下去：A 改了 → 主组件 M 里 A 的实例跟着改 → M 变了 → M 的实例跟着改。只有最外层的实例（没有 `source` 的）直接照它的主组件同步，嵌套在实例里的靠外层传下来。主组件里对嵌套实例的覆盖照样传给 M 的实例。
- 副本的血缘（`lineageId`）由所在实例的血缘和主组件节点的 id 算出来：同一个实例复制出来的几页幻灯片里，后来补上的副本血缘也相同，平滑切换配得上。
- 规则：实例里的结构跟着主组件，不能改：实例里的东西不能编组、做布尔运算、做蒙版、调层序、复制、轮廓化、偏移路径、转轮廓；删除等于隐藏（一项覆盖，重置就回来了）。主组件不能放进主组件，主组件里不能直接或间接出现自己的实例（编组会把对象挪进最下面那个对象所在的容器，挪进去违反规则的不让编）。命令里检查这些，打开文件时 `validate.ts` 也检查（主组件套主组件、互相包含成环都拒绝）。
- 命令：创建组件（只选一个普通编组时直接标成主组件，否则先编组；序号单独数，默认名"组件 1"）、放一个实例（视口中间，或者拖到画布上松手的地方；放的位置违反规则时放到页面上）、分离实例（变成普通编组；里面嵌套的实例变成最外层的实例，副本改成直接对应它自己的主组件，一路上的覆盖合在一起保留；对应不上的嵌套实例一起分离）、重置实例（去掉覆盖；选中实例里的某个对象时只重置它）、跳到主组件（幻灯片视图里切到那一页，画布视图里挪到视口中间）。取消实例的编组时先分离；取消主组件的编组后实例还在，只是不再同步（和删掉主组件一样）。
- 界面：图层列表里主组件、实例和实例里的东西用组件色（紫色）和各自的图标标出来。左栏"资源"页列出主组件（缩略图；单击放一个实例，拖到画布上放在松手处，双击改名，旁边的按钮跳到主组件）。属性栏的"组件"面板：选中主组件时显示有几个实例、放一个实例；选中实例时显示是哪个组件的实例、改过几项，可以跳到主组件、重置、分离；选中实例里的对象时说明能改什么，可以在主组件里找到它、只重置它；其余能做成组件的选区显示"创建组件"。

验证：单元测试检查样式（改样式时对象跟着变、一步撤销，手动改了断开，删样式断开，文字样式保留单独加粗的字，套用时清掉单独设的同一项，校验）、组件（副本、同步、覆盖和改回、文字的覆盖组、加删调换子节点、编组连同内容补进实例、复制出来的实例、蒙版跟着主组件、重置、分离、两层嵌套的同步和分离后的覆盖、规则、打开文件时拦住成环、血缘），以及编辑器里的命令（创建、放置的位置、实例里不能改结构、删除等于隐藏、整体缩放后照样同步、取消实例的编组、颜色样式拖动取色器是一步撤销、文字样式重新定义、主组件和实例里链接样式的颜色一起变）。在 Chrome 里实测：选中矩形和文字做成组件、放实例；改主组件的颜色和大小，实例跟着变；把实例拖大一倍后主组件再改，照样同步；双击进实例改填充，主组件不受影响，面板显示改过 1 项；在实例里打字改文字，主组件改了文字和字重，实例的文字保留、字重跟着变；从文字颜色新建颜色样式、从文字新建文字样式，改样式后主组件和实例的文字一起变；从资源页拖组件到画布（用脚本派发拖放事件，自动化的鼠标拖动触发不了 HTML5 拖放），实例的中心正好在松手处；有缩放过的实例的画板导出 SVG（文字转轮廓）和导出 PNG 逐像素比较，差异明显的像素 0.28%，都在文字边缘。

还没做的：

- 换实例的主组件（数据上支持，整理器会重新同步，界面上没有入口）；跨文档的组件库。
- 约束和自动布局：实例只能整体缩放，非等比拉伸时文字也跟着拉扁；取消缩放过的实例的编组后，缩放留在每个对象的变换矩阵里。
- 渐变样式；描边和文字里个别字的颜色链接样式；样式不能拖动排序、分组。
- 画布上的选区框不按组件色画；创建组件、分离实例没有快捷键（快捷键表已经能按物理键匹配 Option 加字母，见"输入与快捷键"一节）。

### 模板

用户 2026-11-27 要的三种都做了：新建时的模板库、存为模板、幻灯片版式。版式在 core（`layouts.ts`），模板在界面层（`apps/web/src/templates`），新建对话框是 `components/NewDocumentDialog.tsx`。

**样式的用途**：颜色样式、文字样式多了一个可选的 `role`（颜色：背景、文字、强调色、次要文字；文字：标题、副标题、正文、注释）。版式按用途取样式，所以模板定好了配色和字体，之后按版式新建的幻灯片就用模板的，并且链接上这些样式，改样式时整份稿子一起变。省略时和以前一样，打开文件时只要求它是短字符串（更新的版本加的用途不拒绝，版式用不上而已）。界面上还不能给自己的样式指定用途，只有内置模板里有。

**幻灯片版式**（`core/src/layouts.ts`）

- 八个：空白、标题页、标题和正文、两栏、图文、节标题、只有标题、引用。每个版式是一个函数，按幻灯片的大小摆文本框（固定宽度、自动折行）、图片占位框（灰色矩形，名字是"图片"，选中后在外观面板里换成图片填充）和强调色的短横条。版式放在注册表里，新增一个是写一个函数调用 `registerLayout`，再到语言包里加名字。
- 字和颜色：有对应用途的文字样式时用它并链接，没有时按幻灯片高度换算默认字号（720 高时标题 52、正文 24）、用编辑器的默认字体；有"文字""强调色""次要文字"颜色样式时用它们并链接，没有时按背景的深浅选深色或白色的字。正文每行一个项目符号。占位的文字由界面层按当前语言给（内核不产生给人看的文字）。
- 新建幻灯片（`artboard.add`）可以带版式：新的一页沿用当前页的大小和背景（文档里有"背景"颜色样式时链接它），版式里的对象和新的一页是一步撤销。以前新建的一页总是白底，现在跟着当前页，深色的稿子加页不会突然变白。
- 界面：幻灯片条上的"+"换成版式菜单，每个版式一张示意图。
- 文字的高度要排版以后才知道，版式按一行估算往下排：标题很长折成两行时会压到下面的正文，要自己挪。

**新建时的模板库**（文件菜单"新建…"）

- 空白：演示 16:9（1280 × 720，和以前的默认画板一样）、演示 4:3、A4 竖版和横版（按点，595 × 842）、海报 A2、社交方图、手机竖屏、横幅。演示稿的画板是幻灯片，其余是普通画板。
- 内置模板（`templates/builtin.ts`）：简约演示（七页）、深色演示（五页，衬线标题）、活动海报（A4，渐变背景）、社交方图。每个模板是一个函数，示例文字和样式名从语言包取，中文界面里打开是中文的示例。演示稿模板用的就是上面的版式，配色和字体做成带用途的样式；页脚做成组件，主组件放在第一页下面、画板以外（导出、演示都不会带上），内容页各放一个实例，改主组件时每页的页脚一起变。
- 预览：新建一个不挂载的编辑器装进模板，等字体加载好画封面的缩略图，画完就扔掉；按模板和语言缓存。为此 `Editor.renderThumbnail` 改成没挂载时用一个只做离屏绘制的渲染器（缩略图本来就画在 CPU 的位图上，不用画布）。
- 选一个就换成新文档（有没保存的修改时先问），是一份还没保存过的文档；有幻灯片的进幻灯片视图，没有的进画布视图。

- 占位框是真的文字，要自己删掉重写，没有"单击添加标题"那种点进去就清空的占位；图片占位框没有一键换图。
- 界面上不能给样式指定用途；文字样式里没有段落参数（对齐、段距）。
- 模板库没有分类、搜索，内置模板只有四个、没有图片素材；我的模板只存在本机浏览器里，没有云端。
- 画布视图里没有新建画板的入口，版式菜单只在幻灯片条上。

### 文件格式与存储

- **.shiba 文件**是一个 ZIP 包：`manifest.json`（格式标识、版本、资源清单）、`document.json`（节点表）、`assets/<内容哈希>.<扩展名>`（图片）。图片已经压缩过，原样存入不再压缩。把扩展名改成 .zip 就能用普通工具解开。
- 保存时只写入文档实际引用的图片，撤销掉或换掉的图片不占体积。
- **打开文件按不可信输入处理**：只读取认识的条目，限制解压后的总大小，文档结构要过校验（字段类型、数值有限、父子关系不成环）。校验不通过就拒绝打开，当前文档不受影响。不认识的节点类型会放行，方便旧版本打开新文件。
- **保存方式**：浏览器支持文件系统访问接口时（Chrome、Edge）直接写回用户选的文件；不支持时（Safari、Firefox）退回成下载。
- **本地草稿**：正在编辑的文档自动存在 IndexedDB 里，刷新或意外关闭后能接着做。文档每次修改后重写，图片只在第一次出现时写一次。草稿不等于保存文件。
- **导出 PNG、JPEG**：导出当前画板或选中的单个对象，支持 1 倍和 2 倍，单边上限 8192 像素。导出前会等文本用到的字体全部加载完。画板按自己的大小导出；别的对象按画出来的范围（`GeometryCache.drawnBounds`：几何边界加上描边，端点、拐角都算），原来按几何边界裁，带描边的对象导出来描边外侧那一半被切掉了。JPEG 用浏览器的编码器（渲染引擎的默认构建不带 JPEG 编码器）：先导出 PNG，画到一块垫了白底的画布上（JPEG 没有透明，不垫的话透明处是黑的），再按 0.92 的质量编码。在 Chrome 里验证过。
- 待做：文件内嵌缩略图、OPFS 存储。

## 8. 主要风险

1. **文本引擎**：中文输入法、字体回退、大字体按需加载是最容易低估的部分。
2. **PDF 文本重建**：多栏、表格、缺字体这类长尾问题会持续很久。
3. **布尔运算稳健性**：PathOps 的失败情况必须有回退路径和回归测试集。
4. **范围**：每个阶段的验收标准当作硬边界，否则公测时间会一直后移。
5. **CanvasKit 体积**：WASM 文件 7.3MB，gzip 后约 3MB，首屏要做加载优化。
6. **CanvasKit 的类型声明与实际不完全一致**：0.42 版声明了 `path.makeCombined`，但默认构建里没有。用到新接口时要实测。
7. **平板内存**：iPad Safari 对大画布和大图的内存限制很紧。
