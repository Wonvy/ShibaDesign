## 1. 日常编辑

### EDIT-4 段落样式的补充

段落样式已经有对齐、段前段后距、左缩进、首行缩进、列表（`core/src/paragraphs.ts`、`renderer/src/text/layout.ts`），还缺：

- **悬挂缩进**（负的首行缩进，用在列表以外的段落）。Skia 的段落不支持负缩进，现在首行缩进是段首一个占位符。可能要先排一次找出第一行的断点，再把第一行和其余几行分开排。
- **右缩进**、**每段自己的行高**（现在行高是整个文本的）。
- **列表**：编号从几开始、自定义符号；全局快捷键（快捷键表已经按物理键匹配，Shift+数字可以直接绑，见 [interaction-plan.md 的 KEY-1](interaction-plan.md#key-1-完整的快捷键表)）。
- **打开 PDF 时把项目符号还原成列表**：现在 PDF 里的符号和正文是分开的两个文本（`io/src/pdf/paragraphs.ts`）。要把同一条基线上的符号和段落配对，合成一个带列表样式的文本，同时保住改字之前按原字形显示（保真外观，见 architecture.md"文本"一节）。容易误判，要有足够的样本。

### EDIT-5 文本排版的补充

- **中英文混排的细节**：中英文之间自动加间距、标点挤压、行首行尾禁则。Skia 的段落不直接支持，要么预处理文字，要么自己断行（`renderer/src/text/layout.ts`）。
- **上标、下标**：字符样式加基线偏移（`core/src/text-spans.ts`）。打开 PDF 时的上标现在只保留了小字号，开始编辑后不再抬高。
- **复制粘贴时带上样式**：`editor/src/tools/text.ts` 现在只走纯文字；可以额外写 `text/html` 或自定义格式。
- **Home / End 按视觉行移动**：现在交给隐藏的输入框，按逻辑行移动。
- **表情符号字体**（彩色字体），在 `apps/web/src/fonts.ts` 登记。
- **竖排**、**沿路径排列**（M5）。
- **文字转轮廓的补充**：字形轮廓现在只认 TrueType（glyf 表），CFF 轮廓的字体（用户以后导入的 .otf）转不了，会保持原样（`io/src/font/glyf.ts`，导出 SVG 的"转成轮廓"也一样）。

### EDIT-6 对象操作的补充

- **对齐**：以某个对象为基准对齐（关键对象）、按视觉边界对齐、对齐锚点、拖动调整间距的手柄（`core/src/align.ts`、`apps/web/src/panels/ArrangePanels.tsx`）。
- **布尔运算**：拼合成普通路径、分割、修边；PathOps 算不出来时回退到 Clipper2；双击进入布尔组编辑子对象（`editor/src/commands/boolean.ts`、`renderer/src/nodes/boolean.ts`）。还没有边重合、极短线段这类刁钻情况的回归测试。拼合现在很便宜：把布尔组的轮廓交给 `pathGeometry`（`renderer/src/path-ops.ts`），再用 `editor/src/commands/path.ts` 里的 `replaceNode` 换掉原来的组，和轮廓化描边一样保留 id。
- **偏移路径的补充**：对话框里改距离时画布上没有预览，要点"确定"才看得到；可以用同一个合并键边改边应用，取消时撤销。没闭合的路径外扩时两头是平的（圆角时是圆的），没有单独的端点选项。
- **渐变**：角度渐变（锥形；Skia 有 `MakeSweepGradient`，但 PDF 和 SVG 都没有原生的锥形渐变，导出时要拆成分段或者近似）、描边和文字的渐变（打开 PDF 时这两种现在改成平均色）。
- **描边位置**：内描边、外描边（现在只有居中）。斜接限制固定是 4（Skia 的默认值；PDF 默认是 10，打开 PDF 时没有读它）。

### EDIT-7 在画布上调整填充和蒙版的补充

在画布上拖渐变、在形状里挪动缩放图片、移动蒙版里的内容都有了（见 architecture.md"对象操作"一节，代码在 `editor/src/fill-handles.ts`、`editor/src/tools/select.ts`、`editor/src/overlay.ts`），还可以补：

- 在渐变的连线上显示、拖动色标；拖渐变手柄时吸附到外框的边和中点（现在按住 Shift 只吸附方向）。

## 2. 修图（M2 剩下的）

### IMG-1 抠图

- **要做**：选中图片一键去背景，全在本地运行，不上传图片。按方案用 ONNX Runtime Web 在 Worker 里跑分割模型。结果要是非破坏的：把算出来的透明度蒙版存成资源，作为图片填充的一项调整，可以关掉、可以用画笔修。
- **注意**：
  - 模型必须是可商用的许可，比如 MIT 或 Apache 2.0；有的模型只许非商用，要逐个核实。
  - 模型文件大（几十 MB），第一次用时才下载，要缓存；先试 WebGPU，不行退回 WASM。
  - 导出 PDF、SVG 时把蒙版烤进像素（`renderer/src/bake.ts`）。
- **涉及**：`core/src/model.ts` 的 `ImageAdjustments`、`renderer/src/adjust.ts`、`renderer/src/bake.ts`、`apps/web/src/panels/ImagePanel.tsx`。
- **怎么算做完**：人像、商品图各几张，边缘看得过去；界面不卡；断网也能用（模型已经下载过的话）。

### IMG-2 曲线、锐化、滤镜的补充

曲线、锐化、九个滤镜预设已经有了（见 architecture.md"图片"一节，着色器在 `renderer/src/image-look.ts`），还可以补：

- 曲线编辑器画出图片的直方图；控制点能用键盘选中、移动、删除（`apps/web/src/panels/CurveEditor.tsx`）。
- 导入 .cube 这类 3D LUT 文件当滤镜：文件存进资源库，着色器多一个 3D 查找表（拼成一张 2D 图片取样）；文件按不可信输入处理。用户 2026-11-27 选的是"滤镜 + 强度"，没要 LUT 导入。
- 预设缩略图只显示套在原图上的样子，不带自己调的颜色和曲线。
- 锐化在着色器里按 5 × 5 取样，间隔就是半径；半径比图片像素大很多时取样稀疏，细节多的图上可能出现格子状的痕迹。要更好可以先把图片按半径模糊成一张中间图再相减。

### IMG-3 大图

- 现在长边超过 4096 像素的图片在导入时直接缩小（`apps/web/src/files.ts` 的 `MAX_IMAGE_SIDE`），会损失分辨率。
- 正式方案：保留原图，编辑时用缩小的代理图，导出时用原图；图片在 Worker 里解码。

### IMG-4 Photoshop 独有的混合模式

- 现在有 16 种标准混合模式。PS 独有的 11 种（线性加深、亮光、实色混合等）要用自定义着色器做；PDF、SVG 大多没有对应的写法，导出时只能烤成图片。

## 4. 导入导出

### IO-1 打开 PDF

- **用原文件内嵌的字体直接画字**：现在字形按路径画，几十页的字同时出现在屏幕上时很吃力，所以导入时有总量上限（150 万个点）。pdf.js 能交出字体文件，Skia 能按字形编号画字。
- **改字之后继续用原文件的字体**：要把内嵌字体的字符映射改写成 Unicode，再交给排版引擎。
- 表格、多栏（现在拼段落不会跨列，但也不还原成表格）；项目符号还原成列表（见 EDIT-4）。
- 图案填充、网格渐变。
- 软蒙版的背景色（BC）和转换函数（TR）。
- 有密码保护的 PDF。
- 设计软件导出的 PDF 还没有系统地测过，样本还少（见 QA）。

### IO-2 导出 PDF

- 中文两端对齐拉开的字距：有的阅读器（比如 pdf.js）复制文字时会把它当成词间隔，复制出来是"导 出 文 字"。
- 改过的文字用回原文件的字体（依赖 IO-1）。
- 画板以外的对象不导出；PDF/A、PDF/X、超链接、书签、无障碍标签都没有。

### IO-3 导出 SVG

- 复制文字时会断开的两种情况：模拟斜体所在的家族同时用到了真正的斜体文件；从 PDF 导入的、方向不同的几段字。
- 排版用的 WOFF2 和嵌入用的 WOFF 字形编号不一致的分片里，连字、变体这类查不到字符的字形可能写错（`renderer/src/text/shaped.ts` 的 `remapToEmbedded`）。
- 用 Safari、Firefox，以及 Illustrator、Figma、Inkscape 打开看效果。

### IO-4 其他格式和存储

- .shiba 文件里内嵌缩略图；本地存储改用 OPFS。
- 打开 PPTX、PSD（M4）。和 AI、PPTX 的完整双向保真不做（见 architecture.md"不做"）。

### PROD-1 组件与样式的补充

组件（主组件、实例、覆盖、整体缩放、嵌套）、颜色样式、文字样式已经有了（见 architecture.md"组件与样式"一节，代码在 `core/src/components.ts`、`styles.ts`、`editor/src/commands/component.ts`、`style.ts`），还可以补：

- **换实例的主组件**：把 `instanceOf` 改成别的组件，整理器会重新同步（副本对应不上的全部换掉，覆盖丢掉）。要做的是界面入口（组件面板里一个下拉），以及尽量按名字对上同名的子节点保留覆盖。
- **约束和自动布局**：现在实例只能整体缩放（缩放写在变换矩阵里），非等比拉伸时文字也跟着拉扁。按钮这类东西要的是"文字不变、底板变宽"，需要给主组件里的对象加约束（靠左、靠右、拉伸、居中）或者自动布局。取消缩放过的实例的编组后，缩放留在每个对象的变换矩阵里，之后再缩放它们是按几何缩放，可以考虑在分离时把缩放烤进几何。约束和自动布局的方案见 [interaction-plan.md 的 UI-2、UI-3](interaction-plan.md#ui-2-约束)。
- **跨文档的组件库**：把一份文档里的组件和样式发布成库，别的文档引用并接收更新。依赖存储方案（IO-4、云同步）。
- **样式的补充**：渐变样式；描边和文字里个别字（字符级样式）的颜色链接样式；样式拖动排序、分组；文字样式里加段落参数（段距、对齐）。
- **画布上的显示**：选中主组件、实例时选区框用组件色画，主组件上方显示组件名；实例里的对象选中时路径面板现在是显示但按钮全灰，可以干脆不显示。
- **快捷键**：创建组件 ⌥⌘K、分离实例 ⌥⌘B（快捷键表已经按物理键匹配，Option 加字母能用了），和别的快捷键一起在 [interaction-plan.md 的 KEY-1](interaction-plan.md#key-1-完整的快捷键表) 里加。
- **性能**：同步时每次要扫一遍所有节点找实例；节点很多时拖动主组件里的东西每帧都扫。可以在存储里维护一张"主组件 → 实例"的索引。

- **画布视图里新建画板**：现在版式菜单只在幻灯片条上，画布视图里没有新建画板的入口。[interaction-plan.md](interaction-plan.md) 里的画板工具（TOOL-1）和画布空白处的右键菜单（CTX-2）会补上。

## 6. 测试和验证上的欠账

- **浏览器**：输入法、播放器、导出 SVG、导出视频、导出 JPEG 都只在 Chromium 内核的浏览器里测过，Safari、Firefox 还没有。中文输入法只用一种真实的输入法实测过。
- **性能**：只测过 504 × 724 的视口、设备像素比 1、一万个简单形状；高分屏和复杂内容没测。iPad Safari 的内存限制没测。
- **布尔运算**：缺刁钻情况的回归测试集（边重合、极短线段）。
- **PDF 样本**：手写的小文件、浏览器生成的文件、系统自带的几份 TeX 和插画文件；设计软件导出的文件还没有系统地测。

## 7. 已知的小问题

- 属性面板很窄时，分段按钮里的字用省略号截短（比如英文界面的"Auto wi…"），没有悬停提示。
- 英文界面的数量词没有区分单复数，用的是中性的写法（比如"All artboards (3)"）。
- 导出 PNG、JPEG 只能导出一个对象或当前画板；选中好几个对象时导出的是画板，不像导出 SVG 那样能把选中的几个合成一张。
- JPEG 的质量固定是 0.92，导出时不能选。
